# Руководство пользователя

Ежедневная работа с Automatika v2 через веб-интерфейс и PWA. Все команды,
которые выполняет интерфейс, доступны и через REST API — см.
[API.md](../developer/API.md).

## 1. Интерфейс

Веб-интерфейс открывается по адресу `http://automatika.local` (или по IP).
Он же устанавливается как приложение — см. [PWA_INSTALL.md](PWA_INSTALL.md).

Четыре вкладки внизу — по задачам, а не по функциям:

| Вкладка | Что внутри |
|---|---|
| **Работа** | Дашборд и текущая фракция — ежедневное управление |
| **Подготовка** | Профили, калибровка насоса, PID-автотюн, проверка датчиков |
| **Диагностика** | Журнал, проверка приводов, health, сеть |
| **Система** | OTA, API-ключ, язык, сведения об устройстве |

Интерфейс оформлен в стиле iOS: системный шрифт, 8pt-сетка, tap-target
44 px, стеклянные шапка и нижняя навигация. Тёмная тема включается
автоматически по настройке телефона.

Индикатор в шапке:

- **Online** — есть WebSocket-соединение, данные обновляются каждую секунду;
- **Offline** — соединения нет; интерфейс раз в 4 секунды пробует
  `/api/state`, а страница показывает offline-заглушку при полной потере сети;
- **Авария** — активен E-STOP или сработала защита; на дашборде появляется
  красный баннер.

## 2. Структура меню

Четыре группы по задачам; одинаковые названия в PWA, на LCD и в Telegram.

```text
РАБОТА        Дашборд · Текущая фракция · Старт/Стоп
ПОДГОТОВКА    Профили · Калибровка насоса · PID-автотюн · Проверка датчиков
ДИАГНОСТИКА   Журнал · Проверка приводов · Состояние · Сеть
СИСТЕМА       Обновление · API-ключ · Язык · О устройстве
```

- «Работа» открывается по умолчанию: 90 % времени пользователь смотрит
  дашборд и управляет процессом.
- «Подготовка» — разовые действия перед запуском.
- «Диагностика» — журнал, health, сеть и сервисные проверки.
- «Система» — OTA, ключ доступа, язык, сведения об устройстве.

Внизу PWA — четыре таба. Внутри таба — список задач; на LCD то же дерево
листается энкодером (если он разведён на плате) или тапом. В Telegram
`/start` показывает четыре inline-группы.

## 3. Первый ключ доступа

Ключа по умолчанию в прошивке нет — это сделано осознанно, чтобы одинаковый
ключ не оказался у всех устройств.

1. Откройте **Система → API-ключ**.
2. Нажмите **«Сгенерировать»**.
3. Ключ создастся, сохранится в браузере и подставится во все запросы.
4. Скопируйте его в надёжное место: при очистке данных браузера ключ
   придётся вводить заново (или генерировать новый, зная текущий).

Пока ключ не создан, устройство принимает **один** bootstrap-запрос
`/api/config/generate-key`. Сделайте это сразу после первого включения, до
подключения к общей сети.

## 4. Дашборд

### Показания

- **Пар (скорр.)** — температура в колонне с поправкой на атмосферное
  давление (BMP280), главная цифра дашборда.
- **Куб** — температура в перегонном кубе (DS18B20).
- **Мощность** — текущая мощность нагрева, %.
- **Отбор** — текущая скорость отбора, мл/мин.
- **Объём** — суммарно собрано головы + тело + хвосты, мл.
- **Этап** — стадия процесса (нагрев, стабилизация, головы, тело, хвосты,
  охлаждение, готово).

График показывает температуру куба и пара за последние ~300 точек.
Он построен на локальном **uPlot 1.6.32** (MIT), без CDN.

### Кнопки

| Кнопка | Действие | API |
|---|---|---|
| **Старт** | запуск процесса по текущему профилю | `POST /api/start` |
| **Пауза** | пауза с сохранением состояния | `POST /api/pause` |
| **Стоп** | остановка, нагрев снимается | `POST /api/stop` |
| **Сброс аварии** | сброс программной защёлки safety | `POST /api/safety` |

Все команды требуют API-ключ. Если ключ не задан, интерфейс покажет
подсказку и предложит перейти в «Настройки».

### Мощность

Ползунок задаёт мощность нагрева в процентах. Значение применяется сразу
после отпускания (`POST /api/power {"power":N}`).

> При E-STOP или срабатывании safety мощность принудительно обнуляется
> независимо от ползунка.

## 5. Этапы и фракции

Устройство делит процесс на фракции по температуре с поправкой на давление:

| Фракция | Ориентир (при 1013 гПа) | Назначение |
|---|---|---|
| Головы | до ~78.5 °C | отбор малой скоростью, отдельно |
| Тело | 78.5–83 °C | основная продукция |
| Хвосты | до ~98 °C | отбор до конца, отдельно |

Пороги заданы в `main/config.h` (`FRAC_HEADS_END_T`, `FRAC_BODY_END_T`,
`FRAC_TAILS_END_T`) и могут отличаться для вашего аппарата. Давление
учитывается, если установлен BMP280: при пониженном давлении вода кипит
раньше, и пороги сдвигаются.

Переключение фракций в автоматическом режиме происходит само; текущая
фракция видна в `/api/env` (`fraction`), на вкладке **Фракции** и в этапе
процесса. Ручной выбор фракции в этой версии не поддерживается: он
конфликтует с автоматикой и защитой. Вкладка «Фракции» показывает текущее
состояние, пороги и собранные объёмы.

## 6. Профили и PID

Профили хранятся в JSON в `/lfs/profiles/` (или на SD). Управление:

```bash
# список
curl -H "X-API-Key: $KEY" http://automatika.local/api/profiles

# прочитать профиль
curl -H "X-API-Key: $KEY" "http://automatika.local/api/profiles?name=default"

# создать/перезаписать
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d @profile.json http://automatika.local/api/profiles

# удалить
curl -X DELETE -H "X-API-Key: $KEY" \
  "http://automatika.local/api/profiles?name=default"
```

Автотюн PID:

```bash
# старт на 80 °C
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"start","target":80}' http://automatika.local/api/autotune

# статус
curl -H "X-API-Key: $KEY" http://automatika.local/api/autotune
```

Автотюн занимает 30–60 минут и требует заполненного куба и работающего
охлаждения. По завершении коэффициенты сохраняются в NVS.

## 7. Журнал событий

Вкладка **Журнал** показывает последние 50 записей. Типы событий: info,
warning, error, emergency, смена этапа, действие пользователя, датчики, сеть.
Журнал хранится в кольцевом буфере на 200 записей; при перезагрузке
сохраняется в NVS/файле (в зависимости от конфигурации).

Журнал требует API-ключ. Без ключа вкладка подскажет, что его нужно задать.

## 8. Восстановление сессии

Если пропало питание в середине процесса, устройство сохраняет снимок
сессии. После включения:

```bash
curl -H "X-API-Key: $KEY" http://automatika.local/api/session
# {"valid":true,"setpoint":...,"volume_ml":...,...}

# продолжить
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"restore"}' http://automatika.local/api/session

# начать заново
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"clear"}' http://automatika.local/api/session
```

Автоматическое продолжение не выполняется: устройство не должно начинать
нагрев без подтверждения человека.

## 9. Резервное копирование

```bash
# выгрузить конфигурацию в файл на SD
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"path":"/sdcard/cfg.json","secrets":false}' \
  http://automatika.local/api/config/export

# отправить в Telegram (если настроен бот)
curl -X POST -H "X-API-Key: $KEY" http://automatika.local/api/backup/telegram
```

`secrets:false` исключает API-ключи и токены из выгрузки. Для полной копии
(включая секреты) используйте `secrets:true` и храните файл в защищённом
месте.

## 10. Язык интерфейса устройства

```bash
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"lang":"en"}' http://automatika.local/api/i18n
```

Поддерживаются `ru` и `en`. Язык влияет на экран устройства; веб-интерфейс
сейчас русскоязычный.

## 11. Уведомления и Telegram-бот

- **Telegram**: настройте токен и chat_id через `POST /api/telegram`,
  проверьте `POST /api/telegram/test`. Бот присылает аварии и завершение
  этапов.
- **Управление из Telegram**: команды принимаются только из сохранённого
  chat_id:
  `/status`, `/run`, `/stop`, `/pause`, `/resume`, `/power 50`,
  `/fraction`, `/setpoint 83.0`, `/log`, `/profile`.
  Inline-кнопки: «Запуск», «Стоп», «Статус», «Журнал», «Сбросить E-STOP».
  `/power` не обходит E-STOP и safety; загрузка профиля из бота не
  поддерживается — только список.
- **PWA push**: Service Worker готов принимать push-сообщения, но серверная
  часть Web Push (VAPID) в прошивке не реализована. Сейчас уведомления
  приходят через Telegram. Это ограничение описано честно, а не имитируется.

## 12. Offline-режим PWA

После установки приложение кэширует оболочку (HTML/CSS/JS/иконки). Если
устройство недоступно:

- открывается страница «Нет связи» с кнопкой «Повторить»;
- команды не выполняются (API всегда идёт в сеть, без кэша);
- при восстановлении связи интерфейс переподключается автоматически.

Важно: офлайн-режим — это только интерфейс. Сам процесс на устройстве
продолжается по последней программе.

## 13. Отбор по SSVC0059

Дополнительный режим отбора HEADS → BODY → TAILS. Он включается отдельно и
**полностью заменяет** старую логику фракций: одновременно два алгоритма
клапаном не управляют. По умолчанию режим выключен.

Где включить:

- PWA: **Подготовка → Вариант отбора** (галочка «Использовать SSVC0059»);
- LCD: **Работа → SSVC** (экран показывает этап, T фиксации, open_time и
  состояние клапана, кнопка «След. этап»);
- REST: `POST /api/ssvc/options` и `POST /api/ssvc/config`.

### 13.1. Как работает

| Этап | Логика | Переход дальше |
|---|---|---|
| HEADS | Периодический отбор `open_time` / `close_time` по таймеру | по таймеру (авто) или вручную |
| BODY | Фиксация `T_fix` **по пару** (с задержкой `T_delay`), отбор `open_time` / `close_time` | `open_time` уменьшается на декремент при `T_пар > T_fix + гистерезис`, пока не станет меньше минимума |
| TAILS | Отбор `open_time` / `close_time` | по температуре куба `T_tails_end` |
| DONE | Выход закрыт, нагрев выключен | — |

В BODY при превышении `T_fix + гистерезис` отбор приостанавливается
(клапан закрыт), а `open_time` уменьшается на `body_decrement_percent`.
Уменьшение выполняется не чаще раза в секунду, чтобы один скачок
температуры не «съел» весь диапазон. Когда `open_time` падает ниже
`body_min_open_time_sec`, этап завершается.

В ручном режиме (`transition_mode = 1`) этапы сами не переключаются:
после исчерпания BODY отбор закрыт, ждите команды «След. этап».

### 13.2. Варианты отбора

| Параметр | Значения | Поле API |
|---|---|---|
| Устройство отбора | Клапан / перистальтический насос | `out_device` (0/1) |
| Режим переходов | Авто / вручную | `transition_mode` (0/1) |
| Режим отбора | Периодический / непрерывный | `select_mode` (0/1) |
| Датчик этапа | T куба / T пара / T колонны | `sensor` (0/1/2) |

«Непрерывный» для клапана означает постоянно открытый клапан, а не ШИМ
50 %: механический соленоид от такого ШИМ дребезжит. Для насоса это
постоянная подача с текущей скоростью.

### 13.3. Параметры

| Параметр | Поле API | По умолчанию |
|---|---|---|
| Таймер голов, с | `heads_timer_sec` | 3600 |
| Головы: открыт, с | `heads_open_time_sec` | 2.0 |
| Головы: закрыт, с | `heads_close_time_sec` | 8.0 |
| Тело: открыт, с | `body_open_time_sec` | 1.5 |
| Тело: закрыт, с | `body_close_time_sec` | 8.5 |
| Тело: гистерезис, °C | `body_hysteresis_c` | 0.2 |
| Тело: декремент, % | `body_decrement_percent` | 10 |
| Тело: минимальный open_time, с | `body_min_open_time_sec` | 0.1 |
| Тело: задержка фиксации T, с | `body_temp_fix_delay_sec` | 0 |
| Хвосты: температура окончания, °C | `tails_temperature_end` | 98.0 |
| Хвосты: открыт, с | `tails_open_time_sec` | 1.0 |
| Хвосты: закрыт, с | `tails_close_time_sec` | 9.0 |

Период этапа = `open_time + close_time`. В API он по-прежнему доступен как
`heads_period_sec`, `body_period_sec`, `tails_period_sec` (только чтение и
совместимость при записи).

Тайминги под режим (галочка «Профиль режима» в «Варианте отбора»):

| Режим | open, с | close, с | Устройство |
|---|---|---|---|
| Дистилляция | 0.5 | 4.5 | насос |
| Ректификация | 1.5 | 8.5 | клапан |
| Пиво и остальные | непрерывный | — | насос/клапан |

Любое ручное изменение параметра отключает авто-подстановку, чтобы не
потерять настройку при следующем старте.

Конфиг хранится в NVS (`ssvc/cfg`) и переживает перезагрузку. Значения по
умолчанию заданы в `main/config.h` (`SSVC_*`).

### 13.4. REST API

```bash
# состояние: этап, T_fix, open_time, клапан
curl http://automatika.local/api/ssvc/state

# полный конфиг
curl http://automatika.local/api/ssvc/config

# вариант отбора и включение режима
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"enabled":true,"out_device":0,"transition_mode":0,"select_mode":0,"sensor":0}' \
  http://automatika.local/api/ssvc/options

# параметры этапов
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"heads_timer_sec":3600,"body_decrement_percent":10,"tails_temperature_end":98}' \
  http://automatika.local/api/ssvc/config

# принудительный переход на следующий этап
curl -X POST -H "X-API-Key: $KEY" http://automatika.local/api/ssvc/next

# точечное редактирование параметра (inline-редактор)
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"name":"open_time_sec","value":1.5}' \
  http://automatika.local/api/ssvc/param

# начальная заливка для расчёта остатка спирта
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"volume_ml":20000,"abv_percent":40}' \
  http://automatika.local/api/alcohol
```

`GET /api/ssvc/state` возвращает этап, `t_fix`, `open_time`, `close_time`,
`period`, `countdown`, `valve_open`, `ethanol_ml` и `ethanol_percent`.
`GET /api/ssvc/config` и `GET /api/alcohol` доступны без ключа, как и
остальная телеметрия. POST-запросы требуют `X-API-Key`.

### 13.5. Редактирование параметров по тапу

На дашборде PWA карточка **ОТБОР · SSVC0059** содержит строки:

- **T фиксации** — температура пара, при превышении которой начинается
  декремент;
- **Время открыт** — `open_time` текущего этапа;
- **Время закрыт** — `close_time` текущего этапа;
- **Остаток спирта** — справочная строка, не редактируется.

Тап по строке открывает системный ввод, после подтверждения вызывается
`POST /api/ssvc/param`. Изменение применяется сразу (и к текущему циклу) и
сохраняется в NVS. Если процесс не запущен, параметр меняется для этапа
BODY.

На LCD те же строки открывают модальное окно: тап — вход, `−`/`+` —
изменение, `OK` — сохранить, «Отмена» — выйти. Энкодер работает так же:
поворот меняет значение, нажатие подтверждает. В Telegram —
`/param open_time_sec 1.5`.

### 13.6. Индикаторы клапана

- **PWA:** кружок слева от надписи «Клапан». Красный — закрыт, зелёный
  пульсирующий — открыт.
- **LCD:** такой же кружок на экране SSVC; при открытом клапане он
  пульсирует, при закрытом — красный.
- **Telegram:** `/status` показывает этап и остаток спирта; состояние
  клапана видно в `/fraction` и на экране устройства.

Индикатор отражает фактическую команду `apply_output()`, а не только
расписание: при E-STOP или срабатывании safety он всегда красный.

### 13.7. Остаток спирта — как считается

Оценка ведётся в `control/alcohol_balance.c` и обновляется в safety-задаче
каждые 500 мс по температуре куба и абсолютному давлению:

1. По начальному объёму и крепости вычисляются моли этанола и воды.
2. По уравнению Антуана считаются давления насыщенных паров (T в кельвинах,
   P в барах) и коэффициенты активности Ван-Лаара для смеси этанол-вода.
3. Давление насыщения смеси сравнивается с `P_абс`: если куб не кипит,
   потерь нет.
4. Мольная доля этанола в паре определяется по закону Рауля—Дальтона.
5. По текущей скорости отбора (`body_rate_ml_min`) вычисляется, сколько
   молей пара ушло, и остаток этанола уменьшается по Рэлею.

Это **оценка**, а не измерение: она не учитывает пену, брызгоунос и
точную мощность нагрева. Начальные объём и крепость задаются в
**Параметры SSVC → Заливка куба** или `POST /api/alcohol`; при старте
процесса расчёт сбрасывается к этим значениям.

`T_fix` теперь фиксируется по пару, а не по кубу: для BODY используется
датчик, выбранный в «Датчик этапа» (по умолчанию T пара с поправкой на
давление). T куба остаётся в графике, safety и условии окончания хвостов.

### 13.8. Ограничения

- SSVC не отключает E-STOP и safety: при аварии или потере связи с
  датчиками выход принудительно закрывается.
- Режим работает только во время запущенного процесса. При остановке
  SSVC закрывает выход.
- Управление нагревом по этапам SSVC приблизительное (40 % / 60 % / 75 %);
  точную температуру держит PID, если он настроен.
- SSVC применяется к дистилляционным режимам (дистилляция, ректификация,
  ПВК, НБК, вакуум, двойная перегонка). Пиво и ферментация идут по своим
  рецептам и PID: включать там SSVC не нужно.
- Расчёт остатка спирта зависит от корректной начальной заливки и
  калибровки скорости отбора. При ошибке в объёме ошибка будет
  пропорциональной.
- Без реальной платы логика проверена только сборкой: клапан, насос и
  датчики требуют проверки на аппарате.

## 14. Жесты

Жесты работают в PWA на телефоне и на LCD (тач FT6336). Порог — 50 px
и 0.3 px/мс: короткое движение остаётся тапом.

| Жест | Где | Действие |
|---|---|---|
| Свайп влево/вправо | Основной контент | Переключение групп: Работа → Подготовка → Диагностика → Система |
| Свайп вправо от левого края | Любой экран | «Назад» (история или дашборд) |
| Свайп влево по строке | Профили | Удалить профиль (с подтверждением в вебе — кнопкой) |
| Свайп влево по строке | Журнал | Действие «Копировать»: события нельзя удалить по одному, в прошивке нет такого API |
| Свайп вниз от верхнего края | Дашборд | Pull-to-refresh: обновить `/api/state` |
| Долгое нажатие | — | В PWA не используется: E-STOP остаётся физической кнопкой, программной кнопки E-STOP нет |
| Haptic | Переключение/действия | `navigator.vibrate(10)` при успехе, 20–40 мс при ошибке (если браузер разрешает) |

На LCD свайп влево/вправо листает группы, свайп от левого края — назад,
свайп вниз на дашборде — обновление. Энкодер с «flick» (3 шага быстрее
150 мс) эмулирует свайп между группами.

## 15. Безопасность

- E-STOP разрывает фазу 220 В механически. Не полагайтесь на кнопку
  «Стоп» в интерфейсе как на аварийную защиту.
- Не оставляйте устройство без присмотра на первых запусках.
- API-ключ — единственная защита REST. Не публикуйте устройство в интернет
  напрямую; для удалённого доступа используйте VPN.
- Самоподписанный сертификат HTTPS не является доверенным, пока вы его не
  установили. Это нормально для локальной сети, но не заменяет проверку
  личности устройства в недоверенной сети.
