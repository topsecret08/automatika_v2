# Automatika V1.0.1 — пошаговая инструкция для начинающих

Эта инструкция проведёт вас через четыре этапа: **подключение**, **прошивку**,
**настройку** и **ежедневное использование**. Если какой-то шаг непонятен,
остановитесь и не продолжайте: ошибка на этапе подключения может привести к
повреждению оборудования или к опасной ситуации.

---

## ⚠️ Сначала прочтите: безопасность

Автоматика управляет **нагревателем (ТЭН) на сетевом напряжении 220 В** и
насосом. Ошибка может вызвать пожар, ожог или поражение током.

1. **Силовую часть (220 В) подключает только человек, который умеет это делать.**
   Если не уверены, пригласите электрика.
2. **Всегда выключайте питание** (автомат и вилку) перед любым подключением
   проводов.
3. **Аварийная кнопка E-STOP обязательна.** Без неё нагрев не запускать.
4. **Аварийное реле** должно быть **замыкающим (NO)**. Нормально замкнутый
   (NC) контакт использовать нельзя: при зависании или пропадании питания
   нагрев включится.
5. **Не оставляйте работающий аппарат без присмотра.**
6. **Не используйте устройство без датчика уровня**, если он предусмотрен
   схемой: без жидкости ТЭН сгорит.
7. Проверьте законность домашней перегонки и пивоварения в вашей стране.
   Инструкция этого не оценивает.

## Часть 1. Что понадобится

**Оборудование:**
- плата **ESP32-S3-N16R8** (16 МБ flash, 8 МБ PSRAM);
- внешняя HMI-панель Waveshare ESP32-S3-Touch-LCD-7 (800×480, RS485) или управление через веб/Android/Windows; встроенный локальный дисплей ST7796/FT6336 в headless-прошивке контроллера не используется;
- датчики **DS18B20** (температура, до 8 штук на одной шине);
- **ADS1115** (аналоговый вход: давление, пролив, поток);
- **HX711** (весы, по желанию);
- **PCA9685** (сервоприводы клапанов, по желанию);
- **YF-S201** (расходомер воды, по желанию);
- датчик уровня-поплавок (по желанию, но рекомендуется);
- **E-STOP** — аварийная кнопка с фиксацией, контакт NC;
- microSD-карта (FAT32, до 32 ГБ) — для справки, рецептов и базы данных;
- блок питания 5 В для платы, отдельно от силовой части;
- USB-кабель для прошивки (данные, а не только зарядка).

**Компьютер:** Windows 10/11, Linux или macOS. Нужен интернет (первая сборка
скачивает компоненты, это занимает несколько минут).

## Часть 2. Подключение

### 2.1. Датчики и шины

| Сигнал | Пин ESP32-S3 |
|---|---|
| I2C SDA (ADS1115, MCP4725, PCA9685, BMP280) | GPIO 8 |
| I2C SCL | GPIO 9 |
| 1-Wire (DS18B20) | GPIO 4 |
| HX711 DOUT / SCK | GPIO 5 / GPIO 6 |
| Расходомер YF-S201 | GPIO 2 |
| Датчик уровня (поплавок) | GPIO 40 |
| E-STOP (NC на GND) | GPIO 7 |
| Пищалка (buzzer) | GPIO 42 |

Полная распиновка — в `docs/hardware/pinout.md` и `main/config.h`.

### 2.2. Дисплей и SD-карта

Пины дисплея и SD-карты уже заданы в прошивке, менять их не нужно:
дисплей — SPI (GPIO 14–18, 21), SD — GPIO 10–13.

### 2.3. Аварийная кнопка E-STOP

1. Установите кнопку с фиксацией (грибок).
2. Контакты кнопки — **нормально замкнутые (NC)**.
3. Один контакт на GPIO 7, второй на GND.
4. Рядом с кнопкой — конденсатор 100 нФ между GPIO 7 и GND (от дребезга).
5. **Проверка:** при нажатии кнопки на экране появится сообщение об аварии.
   Если нажатие ничего не меняет, E-STOP подключён неверно.

### 2.4. Силовая часть (только после проверки всего остального)

```
Сеть 220 В ──► автомат ──► контактор ──► ТЭН
                              ▲
              аварийное реле (NO) ──► SSR/симистор
```

- Аварийное реле — **замыкающее (NO)**. Тот же контакт для SPDT-реле: клемма
  **NO**, а не NC.
- Включает ТЭН **только** контактор, управляемый платой через SSR или
  регулятор (`docs/hardware/finglai_ssvr.md` для Finglai SSVR).
- Подключайте силовую часть, когда датчики на месте и показывают правильные
  значения.

## Часть 3. Прошивка

### 3.0. Самый простой способ: приложение Automatika

Не нужно ничего собирать и устанавливать среду разработки.

1. Скачайте `Automatika-<версия>.exe` из последнего релиза на GitHub
   (подробно — `docs/user/APP.md`).
2. Подключите плату USB-кабелем и запустите приложение.
3. Нажмите **Найти плату** — приложение найдёт порт и возьмёт API-ключ.
4. Нажмите **Обновить до последней версии**. Приложение само скачает
   последний релиз, проверит его и прошьёт плату.

Обновление не начнётся, если процесс запущен. Настройки и история сохраняются.
Подробности — в `docs/user/CONFIGURATOR.md`.

Части 3.1–3.3 нужны, только если вы собираете прошивку сами.

### 3.1. Установка ESP-IDF (один раз)

**Windows (PowerShell):**

```powershell
winget install Espressif.EIM-CLI
eim install -p C:\Espressif -i v5.3.2 -t esp32s3 -a true
C:\Espressif\v5.3.2\esp-idf\export.ps1
```

**Linux / macOS:**

```bash
git clone -b v5.3.2 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3
source ./export.sh
```

### 3.2. Скачивание прошивки

```bash
git clone https://github.com/topsecret08/automatika_v2
cd automatika_v2
```

### 3.3. Сборка и прошивка

Подключите плату USB-кабелем. Узнайте номер порта: на Windows это `COM5`
(или другой номер в диспетчере устройств), на Linux — `/dev/ttyACM0`.

```powershell
$env:PYTHONUTF8=1
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

Первая сборка занимает несколько минут. Когда появится надпись
`Build complete`, прошивка загружается командой `flash`. Окно `monitor`
показывает журнал платы: выйти из него можно сочетанием `Ctrl+]`.

### 3.4. Проверка после прошивки

В журнале должны появиться строки о старте. Через 5 секунд выполняется
самотест (память, PSRAM, SD, I2C, DS18B20, база данных). Если какой-то пункт
падает, посмотрите `docs/service/TROUBLESHOOTING.md`.

## Часть 4. Первая настройка

### 4.1. Wi-Fi

1. При первом включении плата поднимает точку доступа **`Automatika-Setup`**.
2. Подключитесь к ней с телефона или компьютера.
3. Введите имя и пароль домашней сети.
4. Через минуту откройте в браузере **`http://automatika.local/`**
   (или IP-адрес из настроек роутера).

Если сеть не подключилась за 60 секунд, точка доступа поднимется снова.

### 4.2. API-ключ (обязательно!)

Без ключа все изменения настроек запрещены: это защита от посторонних.
Если ключ уже создан, приложение «Automatika» получит его само по USB
(часть 3.0), вводить вручную не нужно.

1. Включите **сервисный режим** (через меню или сервисную настройку NVS).
2. Сгенерируйте ключ:

```bash
curl -X POST http://automatika.local/api/config/generate-key
```

Ответ: `{"api_key":"<32 символа>"}`. **Запишите ключ** и храните его
в надёжном месте. Все дальнейшие команды используют его.

3. Выключите сервисный режим:

```bash
curl -X POST -H "X-API-Key: ВАШ_КЛЮЧ" -d '{"enabled":false}' \
     http://automatika.local/api/diag/service
```

> Не используйте ключи из старых примеров: они известны всем, кто читает
> исходники. Ключ создаётся только на вашей плате.

### 4.3. Датчики и оборудование

1. Откройте в браузере раздел **Подготовка → Оборудование**.
2. Отметьте установленные датчики и исполнительные устройства.
3. Назначьте роли DS18B20: **куб**, **колонна**, **рубашка**, **бак**.
   Роли выбираются по порядку датчиков на шине (сначала подключите один
   датчик и проверьте, какой индекс он получил).
4. Если расходомера воды нет, отключите его в оборудовании (`POST /api/hardware`
   с ключом, тело `{"devices":{"flow":false}}`, см. `SETUP.md`): иначе через 15 с
   нагрева без протока сработает авария `NO_FLOW`.

Проверка готовности каждого режима: `GET /api/hardware`.

### 4.4. Калибровка насоса (если используется шаговый насос)

1. Включите сервисный режим.
2. Дозируйте 10 мл:

```bash
curl -X POST -H "X-API-Key: КЛЮЧ" \
     -d '{"actuator":"pump","action":"dose","ml":10}' \
     http://automatika.local/api/diag/actuators
```

3. Измерьте мерным цилиндром фактический объём (`fact_ml`).
4. Пересчитайте: `steps_per_ml_new = steps_per_ml_old * 10 / fact_ml`
   (по умолчанию `steps_per_ml = 1120`).
5. Запишите результат:

```bash
curl -X POST -H "X-API-Key: КЛЮЧ" -d '{"steps_per_ml":1120}' \
     http://automatika.local/api/config
```

### 4.5. Telegram-уведомления (по желанию)

1. Создайте бота у **@BotFather**, получите токен.
2. Узнайте свой `chat_id` у **@userinfobot**.
3. Пропишите в плату:

```bash
curl -X POST -H "X-API-Key: КЛЮЧ" \
     -d '{"token":"ТОКЕН_БОТА","chat_id":"ВАШ_CHAT_ID"}' \
     http://automatika.local/api/telegram
curl -X POST -H "X-API-Key: КЛЮЧ" http://automatika.local/api/telegram/test
```

Если пришло тестовое сообщение, уведомления работают.

### 4.6. Настройка управления нагревом

- **PID** (плавное управление): `{"ctrl_mode":0}`.
- **Гистерезис** (включено/выключено): `{"ctrl_mode":1,"hys":1.0}`
  (порог в °C).

Отправляется так же, как в примерах выше, на `/api/config`.

## Часть 5. Пользование

### 5.1. Экран и веб-интерфейс

- **Интерфейс:** внешняя HMI-панель по RS485, веб-интерфейс или Android-приложение. Главный экран показывает температуры, мощность
  и состояние процесса. Нажатие на параметр открывает его редактирование.
- **Браузер:** `http://automatika.local/` — тот же функционал, плюс графики.
  Страницу можно установить на телефон как приложение (PWA).

### 5.2. Запуск процесса (перегонка)

1. Проверьте, что **E-STOP отпущен**, а уровень жидкости в норме.
2. На экране выберите режим (например, **Дистилляция**).
3. Нажмите **Старт**.
4. Следите за температурой куба и колонны на главном экране.
5. Процесс делится на этапы: головы, тело, хвосты. Переход между этапами
   происходит автоматически по температуре и времени.
6. По окончании придёт уведомление (если настроен Telegram).

### 5.3. Остановка и аварии

- **Остановка:** остановите процесс на экране или в веб-интерфейсе.
- **E-STOP:** нажмите грибок. Нагрев и насос отключаются сразу.
- **Сброс аварии:** только после того, как:
  - процесс остановлен и нагрев выключен;
  - аварийная кнопка отпущена;
  - уровень жидкости в норме.
  Затем нажмите **Сброс аварии** (или `POST /api/safety`).

Причина аварии записана в журнале: `GET /api/events`.

### 5.4. Частые аварии и что делать

| Авария | Что проверить |
|---|---|
| `SENSOR_FAIL` | датчик DS18B20 отключён, плохой контакт на шине 1-Wire |
| `NO_FLOW` | нет воды в охлаждении, забит расходомер, расходомер отмечен в оборудовании, хотя его нет |
| `DRY_RUN_LOW_LEVEL` | мало жидкости в кубе, долейте и выполните сброс |
| `OVERHEAT_CUBE` | куб перегрет (порог 130 °C), проверьте датчик и нагрев |
| `SPILL_DETECTED` | датчик пролива сработал, проверьте аппарат |
| `E-STOP` | кнопка нажата или обрыв линии |

Полный список: `docs/service/TROUBLESHOOTING.md`.

### 5.5. Обновление прошивки

1. Соберите новую версию (см. часть 3) или скачайте готовый образ `.bin`
   из раздела **Releases** на GitHub.
2. Отправьте команду через HTTPS:

```bash
curl -X POST -H "X-API-Key: КЛЮЧ" -H "Content-Type: application/json" \
     -d '{"url":"https://адрес/automatika_v2.bin"}' \
     http://automatika.local/api/ota/secure
```

3. Плата перезагрузится. Если через 30 секунд работы она стабильна, новая
   прошивка подтверждается. Иначе автоматически вернётся предыдущая.
4. Статус: `GET /api/ota`.

## Часть 6. Резервная копия

```bash
curl -X POST -H "X-API-Key: КЛЮЧ" -d '{"path":"/sdcard/cfg.json"}' \
     http://automatika.local/api/config/export
```

Файл `cfg.json` (без секретов) сохраняется на SD-карту. Храните его
отдельно. Для переноса на новую плату используйте `"secrets":true` и
храните файл как секретный.

## Что делать, если что-то не работает

1. Откройте журнал: `GET /api/events` или окно `idf.py monitor`.
2. Проверьте самотест и состояние датчиков: `GET /api/health`.
3. Загляните в `docs/service/TROUBLESHOOTING.md`.
4. Если проблема не решается, создайте issue на GitHub по шаблону из раздела
   **Issues**, приложив фрагмент журнала (без API-ключа и токенов!).
