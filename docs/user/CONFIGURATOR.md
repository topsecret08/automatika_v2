# Конфигуратор: быстрый старт, USB и прошивка по Wi-Fi

`tools/configurator` — приложение для Windows (и Linux/macOS) на Tkinter:
поиск платы по USB, прошивка, обновление до последней версии, телеметрия,
параметры и журнал.

## Установка и запуск

Для обычного пользователя проще скачать готовый `Automatika-<версия>.exe` из
релиза на GitHub: см. [`APP.md`](APP.md). Собрать самому можно скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File tools\configurator\build_exe.ps1
```

Результат — `dist\Automatika.exe`. Для запуска из исходников:

```bash
pip install -r tools/configurator/requirements.txt
python -m tools.configurator
python -m tools.configurator --host 192.168.1.50
```

Нужны Python 3.9+ с Tkinter, `pyserial` и `esptool` (ставятся из
`requirements.txt`).

## Вкладка «Быстрый старт»

Самый простой путь — одна кнопка.

1. Подключите плату к компьютеру USB-кабелем.
2. Откройте приложение и нажмите **Найти плату**. Приложение опрашивает
   COM-порты командой `AUTOMATIKA?`, узнаёт версию, состояние процесса и
   берёт API-ключ. Ключ сохраняется, вводить его вручную не нужно.
3. Нажмите **Обновить до последней версии**. Приложение:
   - проверяет, что процесс остановлен; если процесс запущен, обновление
     не начнётся;
   - скачивает последний релиз с GitHub и проверяет `SHA256SUMS.txt`;
   - если есть порт прошивки (мост CH34x/CP210x или USB-JTAG), прошивает
     по USB: загрузчик, таблицу разделов, приложение и веб-интерфейс;
   - если порта нет, обновляет только приложение по Wi-Fi. Веб-интерфейс
     этим способом не обновляется: для него нужна прошивка по USB.

Настройки, API-ключ и история процессов при обновлении сохраняются:
прошивка пишет только разделы приложения, загрузчика и веб-интерфейса.

**Скачать последний релиз** — только загрузка и проверка, без прошивки.

## USB-подключение платы

При старте прошивка V1.0.1 включает USB CDC: плата появляется как
виртуальный COM-порт и отвечает на команду `AUTOMATIKA?` одной строкой JSON:

```json
{"name":"Automatika","version":"V1.0.1","running":0,"api_key":"..."}
```

Поле `running` равно `1`, если процесс запущен. Поле `api_key` пустое, если
ключ ещё не создан.

**Важно:** на ESP32-S3 USB CDC использует те же пины 19/20, что и встроенный
USB-JTAG. Если ваша плата программируется через порт самой платы, после
загрузки прошивки с CDC этот порт перестаёт быть доступен для `idf.py flash`.
Для прошивки используйте порт моста (CH34x/CP210x), либо переведите плату в
режим загрузки кнопкой BOOT.

## Подключение по сети

1. Устройство и компьютер — в одной сети.
2. Нажмите **Найти**: mDNS-запрос `automatika.local` и проверка
   `GET /api/health`.
3. Введите API-ключ (создаётся в PWA: **Система → API-ключ**) или получите
   его по USB на вкладке «Быстрый старт».
4. Нажмите **Подключиться**.

Адрес и ключ сохраняются в `~/.automatika/configurator.json`. На POSIX файл
получает права `0600`. Ключ хранится в открытом виде — на общем компьютере
не сохраняйте его.

## Вкладки

**Устройство** — версия, uptime, heap, состояние процесса, мощность,
температуры, safety/E-STOP, состояние NO-реле и loop_verify. Кнопки
«Старт», «Стоп», «Сброс аварии» используют те же проверки, что API.

**Прошивка** — выбор `.bin`, размер и SHA-256, потоковая загрузка по Wi-Fi
с прогрессом и отменой.

**Параметры** — чтение и запись `/api/config` / `/api/control`: режим,
выход отбора, гистерезис, скорости, шаги на мл, регулятор, PWM.

**События** — последние 100 записей `GET /api/events`.

## Прошивка по Wi-Fi вручную

1. Остановите процесс: запущенный процесс блокирует обновление.
2. Выберите образ. Проверьте SHA-256 и размер: больше 3 МБ не пройдёт.
3. Нажмите **Прошить по Wi-Fi**.
4. Приложение отправит `POST /api/ota` с `application/octet-stream` и
   `X-API-Key`, показывая прогресс.
5. Устройство проверит образ, переключит загрузочный раздел и
   перезагрузится. Приложение дождётся `GET /api/health` с новой версией.

Если связь оборвалась до ответа, устройство не переключит раздел: образ
пишется в неактивный слот и активируется только после успешной проверки.
При отказе новой прошивки сработает штатный откат по health-check.

## TLS

По умолчанию сертификат проверяется. Для самоподписанного:

- установите `cert.pem` в доверенные ОС и оставьте проверку включённой;
- либо снимите **Проверять TLS** — только в изолированной сети.

## Ограничения

- USB-прошивка пишет загрузчик, таблицу разделов, приложение и
  веб-интерфейс; NVS, SD-карта и история процессов не стираются.
- На пустой или неисправной плате конфигуратор не может проверить, что
  процесс остановлен, и не начнёт прошивку. Для первой заливки используйте
  `idf.py flash` или `tools/bootstrap.ps1`.
- Одновременно можно обновлять только одно устройство.
- Отмена загрузки по Wi-Fi не откатывает уже переданные байты; неактивный
  слот будет перезаписан при следующей попытке.
- Обновление по Wi-Fi не трогает веб-интерфейс (раздел `assets`).
