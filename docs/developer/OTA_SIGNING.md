# Подпись образа прошивки для OTA

Прошивка принимает обновление по воздуху (URL, загрузка через web; OTA с SD-карты контроллера в текущей конфигурации недоступно, так как SD контроллера отключена)
только если образ подписан. Неподписанный или подменённый образ отклоняется
до выставления загрузочного раздела: текущая прошивка и её раздел не меняются.

## Как устроено

- **Алгоритм:** ECDSA P-256, хеш SHA-256 всех байт образа.
- **Хвост образа** (дописывается в конец `automatika_v2.bin`):

  ```
  [DER-подпись (8..80 байт)][длина подписи, 2 байта BE][ATKSIG01]
  ```

- **Публичный ключ** хранится в прошивке: `main/ota/ota_pubkey.h`
  (несжатая точка, 65 байт). Публичная копия для CI: `tools/keys/ota_sign_public.pem`.
- **Приватный ключ** хранится только в секрете GitHub `OTA_SIGNING_KEY`
  (PEM). В репозиторий он не попадает.
- **Проверка в прошивке:** `main/ota/ota_signature.c`, функция
  `ota_signature_verify()`. Вызывается перед `esp_ota_set_boot_partition()`
  во всех путях: `ota_manager` (URL), `web_api` (загрузка),
  `secure_ota` и `ota_url` (через общий путь `ota_manager_flash_url`).
  Путь `ota_sd` (SD) в коде присутствует, но на контроллере без SD сейчас не используется.

## Что видит пользователь

| Ситуация | Ответ | Состояние устройства |
|---|---|---|
| Подпись верна | обновление ставится, перезагрузка | новая прошивка |
| Образа нет подписи | `image not signed` (HTTP 400 для web) | не меняется |
| Подпись не совпала | `signature invalid` | не меняется |

## Команды

Инструмент: `tools/sign_firmware.py` (зависимость `cryptography`).

```bash
# 1. Создать пару ключей (один раз, на защищённой машине; ключ не коммитить)
python tools/sign_firmware.py keygen --private ota_sign_private.pem --pub ota_sign_public.pem

# 2. Заголовок для прошивки из публичного ключа
python tools/sign_firmware.py header --pub ota_sign_public.pem --out main/ota/ota_pubkey.h

# 3. Подписать образ
python tools/sign_firmware.py sign build/automatika_v2.bin --key ota_sign_private.pem --out automatika_v2-signed.bin

# 4. Проверить подпись публичным ключом
python tools/sign_firmware.py verify automatika_v2-signed.bin --pub ota_sign_public.pem
```

Тесты: `python -m unittest discover -s tools/tests` (файл `test_sign_firmware.py`).

## Выпуск в CI

`release.yml` на теге `v*`:

1. собирает прошивку;
2. подписывает `build/automatika_v2.bin` ключом из `OTA_SIGNING_KEY`;
3. проверяет подпись публичным ключом `tools/keys/ota_sign_public.pem`.
   Если секрет и публичный ключ не совпадают, релиз не выходит.

## Первая прошивка с проверкой

Старые прошивки подпись не знают. Поэтому первую прошивку с проверкой нужно
поставить по USB (через конфигуратор или `esptool`). После этого обновления по
воздуху принимаются только подписанные.

## Замена ключа

Публичный ключ зашит в прошивку, поэтому смена ключа требует прошивки по USB.
Порядок:

1. Создать новую пару ключей, обновить `main/ota/ota_pubkey.h` и
   `tools/keys/ota_sign_public.pem`.
2. Обновить секрет `OTA_SIGNING_KEY`.
3. Выпустить прошивку, поставить её по USB на все устройства.
4. Старый приватный ключ уничтожить или хранить в архиве, если нужна
   проверка старых образов.

Если приватный ключ утрачен, обновлять устройства по воздуху нельзя, только по USB.

## Проверка перед выпуском (bench-тест)

На тестовой плате, на ветке с проверкой:

1. Подписанный образ по URL: обновление проходит, устройство перезагружается,
   `GET /api/ota` показывает новую версию.
2. Образ с изменённым одним байтом (например, в середине): отклоняется,
   `signature invalid`, версия не меняется.
3. Неподписанный образ: отклоняется, `image not signed`, версия не меняется.
4. Те же три случая через загрузку по web (`POST /api/ota`). OTA с SD-карты контроллера сейчас недоступна из-за отключённой SD.
5. После отказа устройство продолжает работать, журнал событий содержит причину.

## Ограничения

- Проверка подписи выполняется чтением флеш-раздела после записи образа.
  Для образа 2,8 МБ это занимает секунды; watchdog кормится в ходе загрузки.
- Подпись защищает от подмены образа при передаче. Сама прошивка и ключ API
  защищаются отдельно (см. [`docs/SECURITY.md`](../SECURITY.md)).
- Secure Boot v2 (подпись загрузчика и приложения на уровне ROM) не включён.
  Это отдельная задача: она требует eFuse, которые нельзя откатить.
