# Калибровки: состояние и действия

Документ описывает калибровки датчиков, клапанов и весов и план эндпоинтов для
приложения. Состояние уже доступно (`GET /api/calib/state`). Действия пока не
реализованы: каждое войдёт отдельным PR с тестами.

## Состояние (готово)

`GET /api/calib/state` (чтение, без роли):

- `sensors`: `state` (0 idle, 1 heating, 2 sampling, 3 compute, 4 done, 5 error),
  `saved`, `reference`, `error`, `offsets` (по датчикам, до 8).
- `scale`: `state` (0 idle, 1 taring, 2 calibrating, 3 ready, 4 error), `ready`,
  `stable`, `grams`, `total_ml`, `flow_ml_min`, `density`, `auto_tare`.
- `valves`: по клапанам (до 3): `active`, `open_count`, `total_open_ms`,
  `measured_ml`, `ml_per_hour`, `ml_per_open`.

## Действия (план)

| Калибровка | Действие | Что делает | Ограничения | Роль |
|---|---|---|---|---|
| Датчики | старт | `sensor_calib_start(min, max)`: нагрев до диапазона, выборка, расчёт | процесс не запущен | инженер |
| Датчики | эталон | `sensor_calib_set_manual_reference(t)` | состояние sampling/compute | инженер |
| Датчики | применить | `sensor_calib_apply_and_save()` | состояние done | инженер |
| Датчики | отмена | `sensor_calib_abort()` | любое активное | инженер |
| Клапаны | старт | `valve_calib_start(idx, ожидаемый объём)` | процесс не запущен, клапан закрыт | инженер |
| Клапаны | открыть на N мс | `valve_calib_record_open(idx, ms)` | только во время сессии | инженер |
| Клапаны | финиш | `valve_calib_finish(idx, мл)` | сессия активна | инженер |
| Клапаны | отмена | `valve_calib_cancel(idx)` | сессия активна | инженер |
| Весы | тара | `scale_tare_now()` | весы готовы | инженер |
| Весы | калибровка по весу | `scale_start_calibration(г)`, затем `scale_calibration_step()` | эталонная гиря на весах | инженер |

## Почему не всё сразу

- **Клапаны открываются физически.** Тест клапана при запущенном процессе может
  сбить отбор. Поэтому каждый запуск проверяет, что процесс остановлен, и
  отказывает с 409.
- **Датчики нагревают кубу** (`sensor_calib_start` ждёт нужный диапазон). Нужен
  отдельный тест на стенде до включения в APK.
- **Весы и клапаны** работают по шагам: APK должен показывать текущий шаг из
  `GET /api/calib/state`, а не повторять весь мастер за один запрос.

## Реализовано

- `GET /api/calib/state` — состояние.
- `POST /api/calib/scale/tare` — тара весов. Роль инженер. Отказ 409, если процесс
  запущен: тара сбрасывает накопленный объём отбора (`total_ml`).
- `POST /api/calib/sensors/abort` — отмена калибровки датчиков. Роль инженер.
  Калибровка датчиков не управляет нагревателем, она только ждёт температуры,
  поэтому отмена безопасна.

## Порядок внедрения

1. Состояние (сделано).
2. Тара весов и отмена датчиков (сделано).
3. Клапаны (с проверкой остановки процесса).
4. Датчики с нагревом (после испытаний на стенде).
5. Калибровка весов по гире.
