# Структура кода и план упорядочивания

Документ фиксирует текущее состояние репозитория, что уже сделано и что
стоит сделать дальше. Цифры измерены по файлам репозитория на момент записи.

## 1. Текущее состояние

| Часть | Объём | Комментарий |
|---|---|---|
| `main/` (C/H) | около 42 600 строк, ~360 файлов | основная прошивка |
| `main/web/web_api.c` | 2246 строк | все HTTP-обработчики в одном файле |
| `littlefs/js/app.js` | 2973 строки | весь интерфейс PWA в одном файле |
| `generate_sdcard.py` | 472 строки (было 4088) | см. раздел 2 |
| `android/` | Kotlin, Compose | меню генерируется из `menu_tree.c` |
| `tools/` | Python | конфигуратор, CLI, генераторы, тесты |
| `docs/` | ~40 файлов | пользователь, сервис, разработчик, железо, юридические |

Подпапки `main/` по числу файлов C/H: `control` 57, `core` 93, `ui` 59,
`web` 40, `hal` 42, `modes` 24, `ai` 16, `ota` 12, `verify` 10, `db` 10,
`net` 6, `level` 2, `third_party` 2, `script` 4.

## 2. Уже сделано

- **Справка SD-карты вынесена из кода.** Тексты 103 статей лежат в
  `sdcard_src/help/*.md`. `generate_sdcard.py` читает их при запуске.
  Проверка: вывод старого и нового генератора сравнён по SHA-256 всех
  138 файлов — совпадают полностью.
- Удалён мёртвый модуль `main/patches/` (функция нигде не вызывалась).
- Меню Android генерируется из исходника дисплея (`tools/gen_android_menu.py`),
  CI проверяет актуальность файла.

| Два модуля клапанов | `control/ctrl_valves.c` (низкий уровень) и `control/ctrl_valve_control.c` (высокий) | слоистая архитектура, но имена похожи | переименовать: `valve_hw.c` и `valve_logic.c` |
| Два экрана | `ui/ui_screens.c` и `ui/ui_screens_full.c` | по имени не понятно, что в каком | разнести по темам: `ui_process.c`, `ui_calc.c`, `ui_settings.c`, `ui_diag.c` |

| `app.js` | 2973 строки | весь интерфейс в одном файле | разбить на модули по страницам; проверить E2E-тестами |

## 4. Риски и порядок работ

1. **Низкий риск, проверяется диффом.** Вынос данных из кода (как справка),
   переименование файлов без изменения логики, разбиение `web_api.c` по
   группам без изменения маршрутов. Проверка: сборка прошивки, модульные
   тесты в QEMU, `gen_api_docs.py --check` (маршруты не меняются).
2. **Средний риск.** Разбиение `app.js`, переименование модулей в `ui/`.
   Проверка: E2E-тесты интерфейса (17 сценариев), ручной просмотр страниц.
3. **Высокий риск.** Удаление второго модуля алкогольного баланса. Меняются
   цифры, которые видит пользователь. Нужна сверка на стенде, до этого не делать.

## 5. Что не нужно делать

- Не переписывать модули, которые уже покрыты тестами, без веской причины.
- Не менять имена публичных маршрутов API и ключей NVS: ломаются приложения
  и сохранённые настройки.
- Не удалять файлы, которые используют тесты (например, `thermal_sim.c`
  и `chaos_probe.c` используются `test/main/test_sim_chaos.c`).
