# Адаптация UI под Waveshare ESP32-S3-Touch-LCD-7 (800×480)

## 1. Главное решение

Не переносить старый UI «как есть» и не масштабировать его механически.

Новый дисплей — **RGB 800×480**, другой драйвер, другой тач (GT911), другая подсветка (CH422G) и другая частота обновления.

Правильный подход:

- **Сохранить** LVGL 8.3.11, тему, стили, билдеры карточек/списков/кнопок и структуру экранов.
- **Заменить** HAL дисплея/тача, числовые константы размеров и источники данных.
- **Переписать** callback-и: они должны слать команды по CAN и рисовать telemetry, а не дёргать `ctrl_*` напрямую.

## 2. Соотношение размеров

```text
Старый: 480 × 320
Новый:  800 × 480

sx = 800 / 480 = 1.667
sy = 480 / 320 = 1.500
```

Использовать **равномерный масштаб `UI_SCALE = 1.5`**:

```text
480 × 1.5 = 720  →  остаётся 80 px по ширине
320 × 1.5 = 480  →  высота совпадает точно
```

Эти 80 px использовать под правую колонку статуса: связь, E-STOP, safety, тревоги, версия прошивки.

### 2.1. Альтернатива: уплотнение вместо 1.5

Масштаб 1.5 — **максимальный равномерный**, потому что по высоте 320 × 1.5 = 480. Больше нельзя: 320 × 1.667 = 533 > 480.

Можно взять меньший масштаб, например **1.25**:

```text
480 × 1.25 = 600   →  200 px свободно по ширине
320 × 1.25 = 400   →   80 px свободно по высоте
```

Это даёт место для:

- третьего столбца карточек;
- правой колонки статуса шириной ~180 px;
- нижней полосы событий высотой ~70–80 px.

Но физический размер элементов уменьшается. При ≈5 px/mm:

| Масштаб | Кнопка 40 px | Ощущение |
|---:|---:|---|
| 1.5 | 60 px ≈ 11.5 мм | уверенное нажатие |
| 1.25 | 50 px ≈ 9.6 мм | допустимо, но теснее |
| 1.1 | 44 px ≈ 8.5 мм | мелко для 7\" пальцем |

**Рекомендация — гибрид:**

- первичные элементы (E-STOP, крупные числа, кнопки Start/Stop, мощность) — масштаб **1.5**;
- вторичные элементы (таблицы, лог, настройки, диагностика) — масштаб **1.2–1.25**;
- ширину не растягивать принудительно, а отдать flex/grid.

Так получается и читаемо, и плоскость используется целиком.

## 3. Что уже хорошо в старом коде

В `main/ui/` уже активно используются:

- `LV_PCT(100)` — ширина на 100% родителя;
- `LV_SIZE_CONTENT`;
- flex-контейнеры: `lv_obj_set_flex_flow(..., LV_FLEX_FLOW_ROW_WRAP)`, `LV_FLEX_FLOW_COLUMN`;
- `ui_style_apply_screen/card/btn/title/subtitle` в `ui_theme.c`;
- билдеры `ui_build_screen_header()`, `ui_build_card_grid()`, `ui_build_list()` в `ui_builder.c`.

Поэтому каркас не переписывается. Меняются:

1. константы размеров/шрифтов;
2. HAL и тач;
3. источники данных;
4. callback-и.

Прямых `480` и `320` в UI почти нет — в основном это `char buf[320]` в `ui_menu.c`, то есть буфер строки, а не координата.

## 4. HAL дисплея и тача

### 4.1. Что заменить

| Старое | Новое |
|---|---|
| Локальный дисплей (legacy) | Waveshare RGB port, 800×480, 16 bpp |
| Тач (legacy) | GT911 I2C, `swap_xy=0`, mirror=0 |
| `PIN_LCD_*` из `config.h` | GPIO из `waveshare_rgb_lcd_port.h` |
| LEDC backlight | CH422G / Waveshare backlight API |
| 2 буфера 480×40×2 = 76,8 КБ | framebuffer 800×480×2 = 768 КБ в PSRAM |

База — пример Waveshare:

```text
waveshare-7/examples/ESP-IDF/08_lvgl_v8_demo
```

Ключевые файлы:

- `components/waveshare_rgb_lcd_port.c/.h`;
- `main/main.c` — регистрация display и touch через `esp_lv_adapter`;
- `main/idf_component.yml` — LVGL `>8.3.9,<9`, `esp_lv_adapter`, `esp_lcd_touch_gt911`.

### 4.2. Инициализация дисплея

```c
#define HMI_H_RES 800
#define HMI_V_RES 480

esp_lv_adapter_display_config_t disp_cfg =
    ESP_LV_ADAPTER_DISPLAY_RGB_DEFAULT_CONFIG(
        panel_handle, NULL, HMI_H_RES, HMI_V_RES, ESP_LV_ADAPTER_ROTATE_0);

disp_cfg.profile.use_psram = true;
lv_display_t *disp = esp_lv_adapter_register_display(&disp_cfg);
```

### 4.3. Тач

Старый костыль из `hal_touch.c`:

```c
x = 320 - raw_x;   // УДАЛИТЬ
```

Новый тач:

```c
esp_lcd_touch_config_t tp_cfg = {
    .x_max = 800,
    .y_max = 480,
    .swap_xy = 0,
    .mirror_x = 0,
    .mirror_y = 0,
};
esp_lcd_touch_new_i2c_gt911(tp_io_handle, &tp_cfg, &touch_handle);
esp_lv_adapter_register_touch(&(esp_lv_adapter_touch_config_t){
    .display = disp,
    .touch = touch_handle,
});
```

### 4.4. Цвет

Если цвета поменялись местами — проверить:

- `CONFIG_LV_COLOR_16_SWAP`;
- `ESP_LCD_COLOR_SPACE_RGB` vs `BGR`;
- `swap_xy` и `mirror_*`.

В пример Waveshare эти параметры уже подобраны — начинать с них.

## 5. Масштабирование геометрии

Создать `firmware_hmi/main/ui/ui_metrics.h`:

```c
#pragma once

#define UI_SCALE        1.5f
#define UI_PX(x)        ((int)(((x) * UI_SCALE) + 0.5f))

#define UI_PAD_XS       UI_PX(4)
#define UI_PAD_SM       UI_PX(8)
#define UI_PAD_MD       UI_PX(12)
#define UI_PAD_LG       UI_PX(16)

#define UI_HEADER_H     UI_PX(56)
#define UI_FOOTER_H     UI_PX(48)
#define UI_BACK_BTN     UI_PX(40)
#define UI_CARD_W       UI_PX(105)
#define UI_CARD_H       UI_PX(90)
#define UI_LIST_ROW_H   UI_PX(58)
#define UI_TOUCH_MIN    UI_PX(48)
```

Пример замены в `ui_builder.c`:

```c
// Было
lv_obj_set_size(hdr, LV_PCT(100), 56);
lv_obj_set_size(back, 40, 40);
lv_obj_set_size(card, 105, 90);
lv_obj_set_size(row, LV_PCT(100), 58);

// Стало
lv_obj_set_size(hdr, LV_PCT(100), UI_HEADER_H);
lv_obj_set_size(back, UI_BACK_BTN, UI_BACK_BTN);
lv_obj_set_size(card, UI_CARD_W, UI_CARD_H);
lv_obj_set_size(row, LV_PCT(100), UI_LIST_ROW_H);
```

Не масштабировать:

- `LV_PCT(...)` — он уже относительный;
- `LV_SIZE_CONTENT`;
- flex/grid pad-ratio;
- координаты, уже посчитанные через `lv_obj_center()` / align.

## 6. Шрифты

Старые размеры и рекомендуемые новые при `UI_SCALE=1.5`:

| Было | Стало |
|---:|---:|
| 12 | 18 |
| 14 | 21 |
| 16 | 24 |
| 18 | 27 |
| 20 | 30 |
| 22 | 33 |
| 24 | 36 |
| 28 | 42 |
| 32 | 48 |

Проблема: в проекте есть только `lv_font_cyr_16` и `lv_font_cyr_24`. Для 800×480 нужно как минимум **сгенерировать `lv_font_cyr_32`** из тех же исходников, иначе кириллица будет мелкой рядом с латиницей.

Порядок:

1. В `ui_theme.c` поменять базовые шрифты:
   ```c
   lv_theme_default_init(NULL, ..., &lv_font_cyr_24);
   ```
2. `ui_style_apply_title()` → 33–36 px.
3. `ui_style_apply_subtitle()` → 21–24 px.
4. Потом пройтись по исключениям `lv_obj_set_style_text_font(...)` в `ui_welcome.c`, `ui_roles.c`, `ui_screens.c`, `ui_welcome.c`.

Лучше вынести размеры шрифтов в `ui_metrics.h`, чтобы не править 40 файлов вручную.

## 7. Компоновка экранов

### 7.1. Главный экран

Старый `ui_screen_home.c` использует карточки `lv_pct(48)`. На 800 px это ~384 px — нормально, но лучше:

```text
┌───────────────────────────────┬──────────┐
│  Header (84 px)               │  STATUS  │
├───────────────┬───────────────┤  COLUMN  │
│  Card 1       │  Card 2       │  80 px   │
├───────────────┼───────────────┤          │
│  Card 3       │  Card 4       │  LINK    │
├───────────────┴───────────────┤  ESTOP   │
│  KPI row / buttons            │  SAFETY  │
└───────────────────────────────┴──────────┘
```

### 7.2. Меню и списки

`ui_build_list()` уже использует flex column и `LV_PCT(100)` — оставить. Увеличить только высоту строки до `UI_LIST_ROW_H`.

### 7.3. Модальные окна

В `ui_screen_selection.c` есть фиксированные `340×200`, `72`, `96` и т.п. Их тоже обернуть в `UI_PX()`.

## 8. Разделение логики и данных

Это самое важное при выносе UI на отдельную плату.

### 8.1. Что НЕ копировать в HMI

Прямые вызовы:

```c
state_get()
ctrl_heater_get_percent()
ctrl_safety_ok()
estop_is_pressed()
events_log()
process_control_start()
```

Они остаются на контроллере.

### 8.2. Что использовать в HMI

| Старый источник | Новый источник в HMI |
|---|---|
| `state_get()` | кэш последнего `TELEMETRY` |
| `tc`, `ts` | `telemetry.tc`, `telemetry.ts` |
| `p` | `telemetry.p` (мощность) |
| `sa` | `telemetry.sa` |
| `es` | `telemetry.es` — только отображение |
| `lv` | `telemetry.lv` |
| `run`, `pause`, `stg` | telemetry |
| `events_log()` | локальный лог + `ev[]` из telemetry |
| `ctrl_heater_set_percent()` | `CMD {"cmd":"power",...}` |
| `process_control_start()` | `CMD {"cmd":"start"}` |

### 8.3. Пример callback-а

```c
static void cb_power(lv_event_t *e) {
    int pct = lv_slider_get_value(s_power_slider);
    hmi_can_enqueue_cmd(buf);   // CMD по CAN
    // НЕ вызывать ctrl_heater_set_percent()!
}
```

## 9. Производительность

Новый экран в 2,5 раза больше по пикселям:

```text
153 600 px (legacy ref)
800×480 = 384 000 px   → ×2.5
```

Рекомендации:

1. Стартовый FPS — **30**, не 60.
2. Адаптивные уровни для HMI:
   ```c
   FPS_ACTIVE = 30
   FPS_NORMAL = 20
   FPS_IDLE   = 10
   FPS_DOZE   = 2
   ```
3. На время портирования отключить тяжёлые тени и анимации:
   - `ui_style_apply_card()` → `shadow_width = 0`;
   - `lv_scr_load_anim()` → обычный `lv_scr_load()`.
4. Не держать два полных кадра 800×480 в PSRAM без нужды. Использовать bounce buffer примера Waveshare или 2 буфера по 800×20×2 = 32 КБ.
5. Включить `LV_MEM_CUSTOM`, `LV_MEMCPY_MEMSET_STD`, `CONFIG_LV_COLOR_DEPTH_16`, как в демо Waveshare.

## 10. Порядок портирования

| Фаза | Работа | Критерий |
|---|---|---|
| 1 | Поднять RGB + GT911, показать прямоугольник | цвета верные, тач кликает в точке |
| 2 | Перенести тему и `ui_metrics.h` | заголовок/карточка выглядят одинаково |
| 3 | Перенести главный экран | 4 карточки + KPI + кнопки |
| 4 | Подключить telemetry | значения обновляются 1 Гц |
| 5 | Добавить статус связи/E-STOP | `NO LINK` и `ES=1` видны сразу |
| 6 | Перенести Управление/Отбор/Профили | команды уходят по CAN |
| 7 | Перенести журнал/диагностику | CRC, ретраи, версия |
| 8 | Оптимизация FPS/памяти | 30 FPS без просадок 24 ч |

Не переносить в первую очередь: Lua, SD-экспорт, расширенную калибровку датчиков, Telegram/MQTT-настройки — они остаются на контроллере/PWA.

## 11. Приёмка

| Критерий | Значение |
|---|---|
| Разрешение | 800×480, без обрезки |
| Тач | совпадает с пальцем, нет `320-x` |
| Шрифт | кириллица читается с 1 м |
| Touch target | ≥48 px после масштаба |
| телеметрия | ≤1.5 с задержки |
| E-STOP | ≤1 с на экране |
| Нет связи | крупным текстом `НЕТ СВЯЗИ`, без локальной логики безопасности |
| FPS | 30 в active, 2 в doze |
| Память | framebuffer в PSRAM, без overflow |
| LVGL | остаётся 8.3.x |

## 12. Частые ошибки

| Ошибка | Почему | Лечение |
|---|---|---|
| Картинка «зеркальная» | swap/mirror другие | сверить с Waveshare example |
| Тач на 80 px правее | остался `320-x` | удалить старый маппинг |
| синий вместо красного | `LV_COLOR_16_SWAP` | переключить в sdkconfig |
| Текст мелкий | не сгенерирован cyr_32 | добавить шрифт |
| Просадки 10 FPS | полный redraw 800×480 | снизить FPS, убрать shadows |
| Кнопки не нажимаются | touch indev не зарегистрирован | `esp_lv_adapter_register_touch()` |
| Старый UI дёргает safety | скопированы callback-и | заменить на `CMD` |

## 13. Готовый прототип гибрида

Создан минимальный рабочий прототип:

```text
firmware_hmi/
├── main/ui/
│   ├── ui_metrics.h        // 1.5 / 1.35 / 1.2
│   ├── ui_screen_home.h    // hmi_telemetry_t
│   └── ui_screen_home.c    // раскладка + обновление
├── preview/
│   ├── hybrid_preview.html
│   └── hybrid_preview.png
└── README.md
```

Реализовано:

- 3 карточки в ряд (T1, T2, мощность) — масштаб 1.5;
- строка SET POWER с баром;
- 3 вторичных KPI (БАРО, ПОТОК, ФРАКЦИЯ) — масштаб 1.2;
- правая колонка STATUS шириной 180 px (LINK, E-STOP, SAFETY,
  уровень, этап, версия, CRC);
- нижняя полоса событий 77 px;
- `NO LINK` гасит KPI, но **не скрывает E-STOP**;
- HTML-превью с кнопками LINK/E-STOP/UPDATE VALUES.

Прототип нужно только подключить к разбору кадра `TELEMETRY (0x81)`
вместо ручного заполнения `hmi_telemetry_t`.
