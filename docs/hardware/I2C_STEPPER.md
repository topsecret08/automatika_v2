# I2C-драйвер шагового двигателя

Модуль управляет внешним драйвером по I2C: дозатор и мешалка. Прошивка
не привязана к конкретной микросхеме — важен протокол кадров, описанный
ниже. Транспорт: `main/hal/i2c_stepper.c`, протокол:
`main/core/stepper_proto.{h,c}`, сервис: `main/control/ctrl_stepper.c`.

## Подключение

| Сигнал | Куда | Примечание |
|---|---|---|
| SDA | I2C ESP32-S3 | подтяжка 4,7–10 кОм к 3,3 В |
| SCL | I2C ESP32-S3 | 100 кГц, длина провода минимальна |
| GND | общий | обязательно с драйвером |
| VM | силовое питание | отдельно от 3,3 В, с предохранителем |
| E-STOP | аппаратная цепь | разрывает VM, не только логику |

Адрес по умолчанию — `0x20`. Допустимый диапазон `0x08..0x77`.
Питание логики и силовой части должно быть развязано; общий провод —
только в одной точке.

## Кадры

Запрос:

```
AA 55 VER SEQ CMD AXIS LEN PAYLOAD[0..LEN-1] CRC8
```

Ответ:

```
5A VER SEQ AXIS STATE FAULT LIMIT POS[4] SPEED[2] VIN[2] CRC8
```

- все многобайтные поля — little-endian;
- CRC8: полином `0x07`, начальное значение 0, считается по `VER..PAYLOAD`;
- `SEQ` повторяется в ответе, по нему отбрасываются устаревшие ответы;
- длина ответа всегда 16 байт.

## Команды

| Код | Команда | Payload |
|---:|---|---|
| 1 | `PING` | — |
| 2 | `ENABLE` | `u8 on` |
| 3 | `MOVE_REL` | `i32 steps`, `u16 speed_sps`, `u16 accel_sps2` |
| 4 | `MOVE_ABS` | `i32 position`, `u16 speed`, `u16 accel` |
| 5 | `STOP` | — (торможение по пределу драйвера) |
| 6 | `HOME` | `u16 speed` |
| 7 | `SET_POS` | `i32 position` |
| 8 | `HEARTBEAT` | — |
| 9 | `STATUS` | — |
| 10 | `SET_LIMITS` | `u16 max_speed`, `u8 invert` |
| 11 | `RUN_CONT` | `u8 reverse`, `u16 speed` |

`AXIS`: 0 — дозатор, 1 — мешалка.

Состояния (`STATE`): 0 idle, 1 accel, 2 cruise, 3 decel, 4 homing, 5 fault.
Ошибки (`FAULT`): 0 нет, 1 overcurrent, 2 stall, 3 limit, 4 overtemp,
5 driver, 6 protocol. `LIMIT` — битовая маска концевых датчиков.

## Поведение прошивки

- При старте выполняется `PING`; при отсутствии ответа модуль остаётся
  `offline`, система загружается дальше.
- Реконнект — раз в 5 секунд, без блокировки остальных задач.
- `ctrl_stepper_task` опрашивает обе оси каждые 250 мс и пишет событие при
  смене кода ошибки.
- Дозирование: `STATUS` → `MOVE_REL` → опрос до целевой позиции; тайм-аут
  считается по шагам, скорости и ускорению с двойным запасом.
- Дозатор не подменяется GPIO/клапаном, если I2C-модуль включён, но
  offline: это лучше явной ошибки, чем непредсказуемая выдача.
- Если модуль выключен, мешалка управляется реле `RELAY_STIRRER`.
- Любая авария или E-STOP вызывает `STOP` для обеих осей.
- Ручные `move`/`home` разрешены только в сервисном режиме.

## Настройка

`main/config.h`:

| Макрос | По умолчанию | Назначение |
|---|---:|---|
| `STEPPER_I2C_ADDR` | `0x20` | адрес драйвера |
| `STEPPER_MAX_SPEED_SPS` | `1600` | предел шагов/с |
| `STEPPER_ACCEL_SPS2` | `8000` | ускорение |
| `STEPPER_STIRRER_STEPS_PER_REV` | `3200` | шагов на оборот мешалки |
| `STEPPER_POLL_MS` | `250` | период опроса |

`CONFIG_I2C_STEPPER_ENABLE` задаёт начальное состояние. Дальше настройки
хранятся в NVS (`stepper`) и меняются через `POST /api/stepper`.

## API

```bash
curl -H "X-API-Key: $KEY" http://automatika.local/api/stepper

curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"stirrer","on":true,"reverse":false,"rpm":60}' \
  http://automatika.local/api/stepper

curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"dose","ml":10,"rate_ml_min":60}' \
  http://automatika.local/api/stepper

curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"action":"config","enabled":true,"address":32,"steps_per_ml":1000}' \
  http://automatika.local/api/stepper
```

Ответ содержит `enabled`, `online`, адрес, лимиты и состояние обеих осей:
позиция, скорость, питание, концевики.

## Калибровка

1. Включить модуль через `config`, убедиться, что `online:1`.
2. `steps_per_ml`: прогнать 10 мл, измерить объём, пересчитать
   `steps_per_ml = шаги / фактический объём`.
3. `stirrer_steps_per_rev`: один оборот валка вручную или по метке.
4. Проверить направление: при `reverse:false` валок вращается по часовой
   стрелке (если иное — поменять полярность обмотки, не прошивку).
5. Проверить `HOME` и концевые датчики, если драйвер их поддерживает.
6. Имитировать обрыв I2C: `online` должен стать 0, дозирование — вернуть
   ошибку без зависания задачи.

## Ограничения

- Прошивка не содержит драйвера конкретной микросхемы: нужен контроллер,
  реализующий кадры выше.
- `MOVE_ABS`/`HOME` зависят от поддержки в контроллере.
- I2C не является безопасным каналом: аварийный останов должен разрывать
  силовую цепь аппаратно.
