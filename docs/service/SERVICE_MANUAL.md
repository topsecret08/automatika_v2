# Сервис-мануал Automatika

Документ для монтажника и ремонтника. Все команды выполняются на прошивке
V0.5 alfa и соответствуют реальным обработчикам `main/web/*.c`.

> **Безопасность прежде всего.** В устройстве есть 220 В. Все работы по
> разборке, замене SSR, проверке силовой части — только при отключённом
> питании и после разряда конденсаторов (не менее 5 минут). E-STOP —
> механический разрыв фазы; программная защёлка GPIO 27 его **не заменяет**.

## 1. Инструменты и расходники

- Мультиметр (напряжение, сопротивление, прозвонка), токовые клещи.
- Отвёртки PH2 и PZ2, набор шестигранников, пассатижи.
- Термопаста (КПТ-8 или аналог), изоляционная лента, стяжки.
- Термоусадка, клеммы, провод 1.5 мм² для силовой части.
- Опционально: осциллограф, USB-UART (CP2102/CH340), USB-TTL 3.3 В.
- Для прошивки: ESP-IDF 5.3.2, кабель USB-C с передачей данных.

## 2. Разборка

1. Отключите 220 В, выньте вилку из розетки. **Подождите 5 минут.**
2. Открутите 4 винта нижней крышки (M3).
3. Снимите крышку, не тяните за провода.
4. Отсоедините разъёмы: питание 5 В, нагреватель, датчики, клапаны.
5. Извлеките плату, держа за края. Не касайтесь радиатора SSR и
   электролитических конденсаторов.
6. Сфотографируйте расположение проводов до отключения — это экономит
   время при сборке.

## 3. Замена узлов

### 3.1. SSR-40DA (нагреватель)

1. Обесточьте устройство, разрядите конденсаторы.
2. Открутите два винта крепления SSR к радиатору.
3. Отсоедините управляющие (DC 3–32 В) и силовые (AC) провода.
4. Нанесите тонкий слой термопасты на новый SSR, прикрутите к радиатору.
5. Подключите провода по схеме [wiring_diagram.svg](../hardware/wiring_diagram.svg).
6. Проверьте изоляцию мультиметром: сопротивление между силовой частью и
   корпусом — не менее 10 МОм.
7. После сборки выполните тест нагрева (см. §4.2), начиная с 10–20 %.

### 3.2. Датчики температуры DS18B20

1. Датчики подключены к GPIO 4 (1-Wire), питание 3.3 В, pull-up 4.7 кОм.
2. Проверьте, что прошивка видит оба датчика: `GET /api/health` →
   `"sensors"` больше нуля, либо `GET /api/env`.
3. Замена: отсоедините разъём, установите новый датчик, соблюдая полярность
   (VCC / DATA / GND). Перепутанные линии — частая причина `-127 °C`.
4. После замены проверьте показания при комнатной температуре: 20–30 °C.

### 3.3. MicroSD

1. Слот push-push на боковой панели: нажмите до щелчка, извлеките карту.
2. Новая карта: FAT32, до 32 ГБ, Class 10 и выше.
3. Вставьте до щелчка. Прошивка монтирует карту при старте; каталоги
   создаются автоматически (`/sdcard/reports/`, `/sdcard/profiles/`).
4. Проверка: `GET /api/health` → `"sd":1`. Если `0` — карта не смонтирована,
   устройство продолжает работать без неё (уровень `degraded`).

### 3.4. Батарея RTC DS3231

1. Обесточьте, откройте корпус.
2. Извлеките CR2032 из держателя, установите новую плюсом вверх.
3. После включения время синхронизируется по SNTP, если есть Wi-Fi.
   Без сети можно выставить время через `POST /api/settings`.

### 3.5. Модуль ESP32-S3

1. Модуль распаян на плате; замена требует паяльной станции с нижним
   подогревом. Если плата на разъёмах — просто снимите модуль.
2. После замены прошейте bootloader, таблицу разделов и приложение:
   `idf.py -p COMx flash`.
3. Проверьте MAC и калибровку Wi-Fi (выполняется автоматически при старте).

## 4. Сервисный режим и проверка приводов

Сервисный режим разрешает прямые команды исполнительным механизмам в обход
технологической логики. Включайте его только на обесточенной или безопасной
установке.

### 4.1. Включение и выключение

```bash
# включить (нужен API-ключ)
curl -X POST http://automatika.local/api/diag/service \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"enabled":true}'

# выключить
curl -X POST http://automatika.local/api/diag/service \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"enabled":false}'
```

Проверить состояние: `GET /api/diag/status` (ключ обязателен).

### 4.2. Нагреватель

```bash
# 20 % на 5 секунд; после таймера прошивка сама выключает нагрев
curl -X POST http://automatika.local/api/diag/actuators \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"actuator":"heater","action":"on","pct":20,"seconds":5}'

# аварийно выключить
curl -X POST http://automatika.local/api/diag/actuators \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"actuator":"heater","action":"off"}'
```

При `E-STOP` или срабатывании safety команда вернёт отказ, нагрев останется
выключенным.

### 4.3. Клапан и насос

```bash
curl -X POST http://automatika.local/api/diag/actuators \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"actuator":"valve","action":"open"}'

curl -X POST http://automatika.local/api/diag/actuators \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"actuator":"pump","action":"dose","ml":10,"rate":60}'
```

### 4.4. Реле Grove SSR

```bash
# канал 0 — охлаждение, 1 — вода, 2 — мешалка, 3 — резерв
curl -X POST http://automatika.local/api/diag/actuators \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"actuator":"relay","action":"set","ch":0,"state":1}'
```

## 5. Калибровка

### 5.1. Насос дозатора

1. Заполните мерный цилиндр, наберите 10 мл командой
   `POST /api/dose {"volume_ml":10,"rate_mlmin":60}`.
2. Измерьте фактический объём `V_fact`.
3. Пересчитайте `steps_per_ml`:
   `new = old × V_fact / 10`.
4. Запишите: `POST /api/control {"steps_per_ml":<new>}`.
5. Повторите проверку. Допуск: ±3 % на 10 мл.

### 5.2. PID

1. Установите уставку 80 °C в профиле.
2. Запустите автотюн: `POST /api/autotune {"action":"start"}`.
3. Дождитесь завершения (30–60 минут), проверьте `GET /api/autotune`.
4. Коэффициенты сохраняются в NVS автоматически.

### 5.3. Датчик давления BMP280

1. Проверьте адрес: `0x77` (по умолчанию) или `0x76`.
2. `GET /api/env` → `baro.hpa` должен быть 950–1050 гПа.
3. Если показания отличаются более чем на 20 гПа — проверьте питание 3.3 В
   и линию I2C.

## 6. OTA-обновление

1. Скачайте `automatika_v2.bin` из GitHub Releases.
2. Отправьте URL устройству:

```bash
curl -X POST http://automatika.local/api/ota/url \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/automatika_v2.bin"}'
```

3. Следите за статусом: `GET /api/ota`.
4. После перезагрузки прошивка проходит самодиагностику. Если она не
   подтверждена в течение `OTA_CONFIRM_STABLE_MS`, загрузчик откатывается
   на предыдущий слот.
5. Ручное подтверждение (если автоматика отключена конфигурацией):
   `POST /api/ota/confirm`.

> Обновление по URL требует HTTPS с проверкой сертификата. Для локального
> сервера используйте подписанный сертификат или `POST /api/ota` с телом
> бинарника (multipart не поддерживается — передаётся сырое тело).

## 7. Диагностика

В прошивке **нет числовых кодов E01–E08** из ранней редакции ТЗ. Диагностика
построена на:

- `GET /api/health` — уровень `ok` / `degraded` / `fail`, причина в `reason`,
  свободная память, RSSI, SD, датчики, safety/estop;
- `GET /api/events?limit=N` — кольцевой журнал событий (требует ключ);
- `GET /api/diag/status` — состояние сервисного режима и приводов.

Типовые причины `fail`:

| `reason` | Что означает | Действие |
|---|---|---|
| `estop active` | Нажат E-STOP или разорвана цепь | Устранить причину, отпустить кнопку |
| `safety fault` | Сработала защита (уровень, пролив, перегрев) | См. журнал событий, устранить причину |
| `config NVS not ready` | Не смонтировано NVS | Перезагрузить; при повторе — factory reset |
| `low internal RAM: N` | Мало внутренней памяти | Перезагрузить, отключить Lua/лишние задачи |
| `task stale N ms` | Задача не кормит watchdog | Перезагрузить; сообщить разработчику |

`degraded` — устройство работает, но нет SD-карты или ни одного датчика
DS18B20. Это не авария, но точность и журналирование снижены.

## 8. Сброс к заводским настройкам

```bash
curl -X POST http://automatika.local/api/config/import \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  -d '{"reset":true}'
```

Если API недоступен: удерживайте кнопку Reset 10 секунд при включении
(если кнопка подключена на плате). NVS очищается, профили на SD сохраняются.

## 9. Возврат устройства

Приложите:

- версию прошивки (`GET /api/health` → `version`);
- выгрузку событий (`GET /api/events?limit=200`);
- описание условий и последовательность действий;
- фото платы и подключения.

Это сокращает время диагностики. Не отправляйте устройство с остатками
жидкости в баке — слейте и просушите.

## 10. Сессия и параметры на ходу

Сессия — отдельный слой от UI. Уход с главного экрана не останавливает
процесс; навигация по справке, рецептам и журналу безопасна.

| Действие | PWA | LCD | REST |
|---|---|---|---|
| Свернуть | кнопка «Свернуть» | кнопка «Свернуть» | `POST /api/session/minimize` |
| Вернуться | плашка «Работа · этап» | верхняя плашка | `POST /api/session/restore` |
| Состояние | — | — | `GET /api/session/state` |
| Остановить | «Стоп» | «Стоп» | `POST /api/session/stop` + `{"confirm":true}` |

Параметры читаются и пишутся через единый реестр:
`GET /api/param` возвращает список с `value`, `min`, `max`, `step`,
`editable`; `POST /api/param` принимает `{"name":"open_time","value":1.5}`.
Заблокированный параметр возвращает `403` с
`{"ok":false,"error":"locked_while_running"}`.

Правила:

- на ходу разрешены T фиксации, open/close, гистерезис, декремент,
  минимальный open_time, таймер голов, конец хвостов, флегмовое число,
  мощность в ШИМ-режиме;
- уставка PID и калибровка насоса — только до старта;
- параметры безопасности не редактируются из интерфейса;
- мощность в PID-режиме принадлежит регулятору и заблокирована.

При проверке на аппарате: запустить процесс, уйти в другой экран, убедиться,
что нагрев и отбор продолжаются, вернуться плашкой, изменить параметр и
проверить, что новое значение применилось без перезапуска. Если плашка не
появляется — проверить `GET /api/session/state` (`running` и `visible`).

## 11. Внешние регуляторы мощности

UART-регуляторы (KVIC, РМВ-К, SEM) подключаются **только через оптронную
развязку**. Общая земля с силовой частью недопустима: это путь для помех и
поражения низковольтной электроники.

Проверка:

1. `GET /api/control` → `regulator` и `reg_baud`.
2. Задать тип и скорость: `POST /api/control`
   `{"regulator":1,"reg_baud":9600}`.
3. Убедиться, что `REG_UART_TX_GPIO`/`REG_UART_RX_GPIO` заданы и не заняты
   другими функциями.
4. Подать 10 % мощности и проверить реакцию регулятора; при обрыве UART
   вернуть `regulator:0`, чтобы остаться на внутреннем DAC.
5. Проверить, что при E-STOP мощность уходит в ноль независимо от внешнего
   регулятора.

SSR-вариант использует LEDC; GPIO/частота/разрядность/полярность задаются
в PWA/LCD/REST и хранятся в NVS. При `-1` или недопустимом GPIO выход
отключён, `regulator_ready=false`.
Если внешний регулятор не отвечает, `regulator_is_ready()` = false и
`ctrl_heater` продолжает использовать внутренний DAC — это безопасный
дефолт, но требует ручной проверки.
