# Проверка безопасности и обратных связей

Процедура для пусконаладки и периодического обслуживания. Выполняется на
реальном стенде, с нагрузкой и прибором для проверки цепи. Все пункты —
обязательные; при отклонении дальнейшие испытания прекращаются.

## 0. Подготовка

- Прошивка собрана из текущей ветки, версия видна в `GET /api/health`.
- Карта оборудования заполнена: `GET /api/hardware` показывает нужные роли
  датчиков и устройства, все проверяемые режимы — `ready:1`.
- Известны `SAFETY_RELAY_GPIO`, `ACT_READBACK_BACKEND`, `ACT_READBACK_GPIO`,
  `REG_SSR_GPIO`, настройки SSVR.
- Куб заполнен, охлаждение подключено, E-STOP доступен оператору.
- Есть мультиметр и, желательно, токовые клещи.

## 1. E-STOP (NC)

1. Нажать E-STOP при выключенном нагреве.
2. Проверить: `GET /api/state` → `estop:1`, `safety:0`; в журнале
   `SAFETY: E-STOP`.
3. Отпустить кнопку, выполнить `POST /api/safety`.
4. Ожидание: сброс разрешён только при остановленном процессе и нулевой
   мощности; после сброса нагрев не включается сам.

## 2. NO-реле безопасности

Проверяется при `SAFETY_RELAY_GPIO >= 0`.

1. Подать питание. До первого heartbeat реле разомкнуто, контактор обесточен.
2. Убедиться, что после старта safety-задачи реле замкнулось
   (`relay_closed:1` в `GET /api/safety`).
3. Отключить питание MCU при работающем нагреве. Контактор должен
   разомкнуться, нагрев — прекратиться.
4. Восстановить питание, запустить процесс, вызвать аварию (например,
   превышение температуры).
5. Ожидание: `relay_forced:1`, `relay_closed:0`, нагрев 0.
6. Нажать сброс аварии: реле должно остаться разомкнутым до первого
   heartbeat, затем замкнуться.
7. Повторить п. 3 с зажатой кнопкой E-STOP.

## 3. Readback исполнителя

1. `ACT_READBACK_BACKEND=1` (GPIO): включить нагрев 20 %.
   Ожидание: `actual` = 100 %, бинарное сравнение не даёт `ACT_MISMATCH`.
2. Выключить нагрев. Ожидание: `actual` = 0 %, флагов нет.
3. `ACT_READBACK_BACKEND=2` (CURRENT): записать `raw` при 0 %, 50 %, 100 %.
4. Проверить линейность: отклонение от прямой не более 5 % шкалы.
5. Значение `full_scale` занести в конфигурацию; после перезагрузки
   повторить 0/50/100 %.
6. Отсоединить провод обратной связи. Ожидание: `ACT_NO_FEEDBACK` (WARN),
   без ложного CRITICAL.

## 4. Активная верификация контура

1. Запустить процесс, дождаться устойчивого нагрева.
2. Отключить управляющий провод SSR при `cmd > 0`.
   Ожидание: `ACT_MISMATCH` после 3 тактов, `LOOP_VERIFY` CRITICAL,
   нагрев снят.
3. Восстановить цепь, сбросить аварию, повторить запуск.
4. Ожидание: второй запуск не даёт `NO_RESPONSE` из-за паузы между
   прогонами.
5. Имитировать «замороженный» датчик (фиксированное значение).
   Ожидание: `SENSOR_STUCK` не раньше 5 минут, событие однократное.
6. Проверить `GET /api/safety`: `loop_valid:1`, поля `aggregate/flags`
   меняются только при смене состояния.

## 5. Finglai SSVR

1. Проверить соответствие модели, преобразователя и диапазона 0–5/10 В.
2. Установить 0 % — на выходе преобразователя 0 В, нагрузка обесточена.
3. Установить 50 % и 100 % — измерить напряжение и ток нагрузки.
4. Убедиться, что инверсия PWM запрещена и аварийный ноль не даёт
   максимальную скважность.
5. Проверить трёхфазный вариант только при наличии схемы и развязки.

## 6. I2C-степпер

1. Включить модуль через `POST /api/stepper {"action":"config","enabled":true}`.
2. Ожидание: `online:1`, питание `vin_mv` в допустимом диапазоне.
3. Дозировать 10 мл при 60 мл/мин. Проверить фактический объём и позицию
   оси в `GET /api/stepper`.
4. Во время движения нажать E-STOP. Ожидание: обе оси получают `STOP`,
   дозирование возвращает ошибку, процесс не продолжается.
5. Отключить I2C-провод при включённом модуле. Ожидание: `online:0`,
   дозирование возвращает ошибку и **не** переключается на GPIO/клапан.
6. Включить мешалку на 60 rpm, затем реверс. Проверить направление и
   отсутствие рывков.
7. Смоделировать `FAULT` в контроллере. Ожидание: событие `Stepper axis ...`
   и остановка оси.

## 7. OTA и откат

1. Собрать образ с заведомо другой версией.
2. Обновить по HTTPS. Дождаться подтверждения и перезагрузки.
3. Прервать следующий сеанс (не подтверждать) и проверить автоматический
   откат через 30 секунд.
4. Убедиться, что настройки NVS и профили сохранились.

## 8. Журнал и телеметрия

1. Выполнить аварию и сброс.
2. `GET /api/events` — события `SAFETY`, `LOOP_VERIFY` присутствуют,
   WARN не повторяется каждые 500 мс.
3. При активном shadow run проверить в `verify_trace` строку
   `channel='loop'` с `latency_us`, `flags`, `aggregate`.
4. `GET /api/safety` отдаёт состояние реле и последний результат проверки.

## 9. Оформление

Записать в журнал: дату, версию, серийный номер, значения калибровки,
результаты по каждому пункту, подпись оператора. Устройство считается
готовым только при отсутствии отклонений.
