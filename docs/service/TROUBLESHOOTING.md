# Поиск неисправностей (дерево решений)

Диагностика опирается на реальные источники: `GET /api/health`,
`GET /api/events`, `GET /api/env`, `GET /api/diag/status` и журнал
последовательного порта (115200 бод). Числовых кодов E01–E08 в прошивке нет —
вместо них уровень здоровья и текстовые причины.

## 1. Общее дерево

```
Устройство не работает?
│
├─ Нет питания (LED/экран не светятся)
│  ├─ Проверить розетку и кабель 220 В
│  ├─ Проверить F1 (5 A) и УЗО
│  ├─ Проверить 5 В на выходе PS1
│  └─ Проверить, не разомкнут ли E-STOP
│
├─ Питание есть, но нет загрузки
│  ├─ Подключить USB и открыть монитор 115200 бод
│  ├─ Видно `boot: ...` → проблема в приложении/конфигурации
│  │  ├─ `invalid header` / `abort()` → перепрошить (idf.py flash)
│  │  └─ циклическая перезагрузка → посмотреть reset reason
│  └─ Bootloader молчит
│     ├─ Проверить USB-кабель (данные, не только зарядка)
│     ├─ Зажать BOOT при включении, прошить заново
│     └─ Проверить питание модуля 3.3 В
│
├─ Загрузилось, но нет Wi-Fi
│  ├─ Точка `Automatika-Setup` видна → provisioning не завершён
│  ├─ Точки нет, но роутер знает устройство → проверить IP/mDNS
│  └─ Сбросить Wi-Fi: `POST /api/wifi` с новыми данными или
│     перепрошить NVS (см. SERVICE_MANUAL.md)
│
├─ Wi-Fi есть, веб-интерфейс не открывается
│  ├─ `http://automatika.local` не резолвится → использовать IP
│  ├─ Порт 80 занят/не слушается → `GET /api/health` по IP
│  └─ HTTPS не поднялся → смотреть лог `HTTPS: ...`
│
└─ Веб-интерфейс работает, но процесс не идёт
   ├─ `GET /api/health` → `fail` с причиной
   ├─ `GET /api/events?limit=50` → последние ошибки
   └─ `GET /api/diag/status` → safety/estop/приводы
```

## 2. По симптомам

### 2.1. Не греет

1. `GET /api/health` → `estop` должен быть `0`, `safety` — `1`.
2. `GET /api/env` → `flow.ok` и уровень.
3. Включить сервисный режим и проверить нагрев:
   `POST /api/diag/actuators {"actuator":"heater","action":"on","pct":20,"seconds":5}`.
4. Нет нагрева при исправном SSR → проверить:
   - питание 220 В на клеммах SSR;
   - управляющее напряжение 3–32 В от MCP4725 (0x60);
   - целостность нагревателя мультиметром.
5. Нагрев есть, но температура не растёт → проверить DS18B20 (см. 2.3).

### 2.2. Перегрев / захлёб колонны

1. Немедленно снизить мощность: `POST /api/power {"power":0}`.
2. Проверить проток охлаждения: `GET /api/env` → `flow.lpm`.
   Порог безопасности — `SAFE_MIN_FLOW` = 0.5 л/мин.
3. Проверить давление: `GET /api/env` → `column.kpa` и `baro.hpa`.
   Аварийный порог — `SAFE_MAX_PRESSURE` = 3.0 (в единицах датчика).
4. Если температура куба выше `SAFE_MAX_CUBE_T` (130 °C) или царги выше
   `SAFE_MAX_COLUMN_T` (105 °C) — сработает safety, нагрев будет снят
   принудительно.

### 2.3. Датчик температуры показывает `-127 °C` или `85 °C`

- `-127 °C` — обрыв линии DATA или потеря питания датчика.
- `85 °C` — датчик не инициализировался (ошибка CRC/питания).
- Проверить pull-up 4.7 кОм к 3.3 В на GPIO 4.
- `GET /api/health` → `sensors`: если `0`, не найден ни один датчик;
  уровень здоровья станет `degraded`.
- Длина кабеля 1-Wire — не более 10–20 м без активного хаба.

### 2.4. Нет связи по I2C

1. Проверить питание 3.3 В на модулях.
2. Проверить pull-up SDA/SCL (многие модули уже содержат 4.7 кОм;
   при нескольких модулях суммарное сопротивление может оказаться слишком низким).
3. Адреса в прошивке фиксированы: `0x11`, `0x38`, `0x40`, `0x48`, `0x60`,
   `0x68`, `0x77`. Сканирование I2C в прошивке не реализовано — используйте
   внешний сканер или осциллограф.
4. Если не отвечает только BMP280 — проверьте адрес `0x76`/`0x77`
   (у разных модулей SDO подключён по-разному).

### 2.5. Не подключается к Wi-Fi

1. ESP32-S3 работает только в 2.4 ГГц. Сеть 5 ГГц не видна принципиально.
2. SSID и пароль — латиницей; некоторые прошивки роутера отдают SSID
   в не-UTF8 кодировке.
3. WPA3-only не поддерживается — включите WPA2/WPA3 mixed.
4. Сброс сохранённой сети: `POST /api/wifi` с корректными данными или
   `wifi_prov_reset()` (перезагрузка с очисткой credentials).
5. Если точка `Automatika-Setup` не появляется — проверьте, что устройство
   не подключилось к другой сети; посмотрите лог `WIFI`.

### 2.6. PWA не устанавливается

1. Нужен secure context: `https://automatika.local` либо `http://localhost`.
   По `http://<IP>` Service Worker не регистрируется — это правило браузера.
2. Самоподписанный сертификат нужно один раз принять/установить как
   доверенный. Инструкция: [PWA_INSTALL.md](../user/PWA_INSTALL.md).
3. Проверить `GET /manifest.json` — должен отдаваться с типом
   `application/manifest+json`.
4. DevTools → Application → Manifest: иконки 192/512 загружены.
5. DevTools → Application → Service Workers: статус `activated`.
6. На iPhone установка — только через Safari → «Поделиться» →
   «На экран "Домой"».

### 2.7. Телеметрия не обновляется

1. DevTools → Network → WS: подключение к `/ws/telemetry` должно быть
   `101 Switching Protocols`.
2. При `wss://` проверить, что HTTPS-сервер поднялся (лог `HTTPS`).
3. Резервный опрос `/api/state` идёт раз в 5 секунд — если он работает,
   проблема именно в WebSocket.
4. Если не работают и API-команды — проверить `X-API-Key` (для мутирующих
   запросов) и rate limit: 10 запросов/с, burst 20.

### 2.8. OTA не запускается

1. `GET /api/ota` — нет ли уже идущего обновления.
2. `estop`/`safety` должны быть в норме: при аварии OTA отклоняется (409).
3. URL должен быть HTTPS с валидным сертификатом (проверка через CA bundle).
4. Недостаточно места: слот 3 МиБ, текущий образ 22.4 МиБ. При образе
   больше слота обновление не начнётся.
5. После перезагрузки: если health-check не подтвердил образ за
   `OTA_CONFIRM_STABLE_MS`, загрузчик откатится.

### V0.5 alfa. Устройство самопроизвольно перезагружается

1. `GET /api/health` → `reset` (код причины сброса ESP-IDF).
2. `GET /api/events?limit=100` — искать `task stale`, `low internal RAM`,
   `Brownout`.
3. Проверить питание 5 В под нагрузкой (просадка при включении SSR).
4. Проверить, не перегревается ли модуль; проверить антенну и экранирование.
5. Если причина `task_wdt` — сообщите разработчику с логом событий.

## 3. Что приложить к обращению

- версия: `GET /api/health` → `version`;
- `GET /api/health` целиком;
- `GET /api/events?limit=200`;
- лог последовательного порта с момента старта;
- описание: что делали, что ожидали, что произошло.
