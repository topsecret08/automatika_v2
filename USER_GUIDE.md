# Automatika V0.6 beta — руководство пользователя

Кратко о том, как безопасно пользоваться устройством. Технические детали —
в [README.md](README.md), установка — в [SETUP.md](SETUP.md).

---

## Быстрый старт

1. Подключите питание (220 В — обязательно через УЗО и автомат).
2. При первом включении подключитесь к открытой сети **`Automatika-Setup`**
   и передайте SSID/пароль домашней сети через приложение **ESP SoftAP Prov**
   (Espressif) или `esp_prov.py`. Пароля у точки нет — не оставляйте
   устройство в режиме настройки в людном месте.
3. Дождитесь загрузки (≈10 с) и прохождения самотеста.
4. Откройте **`http://automatika.local`** (или IP из роутера, hostname
   `automatika`) — веб-интерфейс. Управление с экрана — меню на дисплее
   480×320.
5. В веб-интерфейсе: **Система → API-ключ → «Сгенерировать»** — создайте
   первый API-ключ. Без него команды управления не выполняются.

## Установка PWA на телефон

Веб-интерфейс можно установить как приложение:

1. Откройте `https://automatika.local` (именно HTTPS, не HTTP по IP).
2. Примите предупреждение самоподписанного сертификата либо установите
   `cert.pem` как доверенный — подробно в
   [docs/user/PWA_INSTALL.md](docs/user/PWA_INSTALL.md).
3. Android/Chrome: кнопка **«Установить»** или меню ⋮ → «Установить
   приложение». Safari: «Поделиться» → «На экран "Домой"».
4. После установки доступны ярлыки «Дашборд», «Журнал», «Настройки»,
   а при потере связи открывается offline-страница.

По `http://<IP>` установка невозможна — браузер требует secure context.
Это ограничение браузера, а не прошивки.

## Структура меню

Меню сгруппировано по задачам, а не по функциям. Одинаково в PWA, на LCD
и в Telegram: четыре группы, внутри — не более четырёх пунктов.

```text
┌─ РАБОТА ─────────────────────────┐
│ • Дашборд                        │
│ • Текущая фракция                │
│ • Старт / Стоп                   │
├─ ПОДГОТОВКА ─────────────────────┤
│ • Профили                        │
│ • Калибровка насоса              │
│ • PID-автотюн                    │
│ • Проверка датчиков              │
├─ ДИАГНОСТИКА ────────────────────┤
│ • Журнал событий                 │
│ • Проверка приводов              │
│ • Состояние (health)             │
│ • Сеть                           │
├─ СИСТЕМА ────────────────────────┤
│ • Обновление (OTA)               │
│ • API-ключ                       │
│ • Язык                           │
│ • О устройстве                   │
└──────────────────────────────────┘
```

- **Работа** — ежедневное управление; открывается по умолчанию.
- **Подготовка** — разовые действия перед запуском.
- **Диагностика** — когда что-то пошло не так.
- **Система** — редкие настройки и обслуживание.

Опасные действия (E-STOP, проверка приводов, OTA) требуют подтверждения
и находятся в конце соответствующей группы.

### Жесты

| Жест | Действие |
|---|---|
| Свайп влево/вправо | Переключение групп: Работа → Подготовка → Диагностика → Система |
| Свайп вправо от левого края | Назад |
| Свайп влево по строке | Профили — удалить; Журнал — копировать |
| Свайп вниз от верхнего края | Обновить дашборд |
| Долгое нажатие | E-STOP остаётся физическим; программной кнопки E-STOP нет |

Порог — 50 px и 0.3 px/мс. На LCD те же свайпы обрабатывает FT6336;
быстрый «flick» энкодера (3 шага < 150 мс) эмулирует свайп между группами.
Анимация: [gestures.gif](docs/user/gestures.gif).

## Датчики и защита (V0.6 beta)

- **Расходомер YF-S201** следит за протоком охлаждающей воды. Если воды
  нет дольше 15 с при включённом нагреве — авария `NO_FLOW`.
- **BMP280** измеряет атмосферное давление: от него пересчитывается
  точка кипения, поэтому фракции не «уезжают» в горах или при смене
  погоды.
- **Давление в колонне** контролируется отдельно; при превышении порога
  `SAFE_MAX_PRESSURE` срабатывает защита `OVERPRESSURE`.
- **Охлаждающий клапан** открывается автоматически на старте и
  закрывается по завершении процесса.
- Если какой-то датчик не установлен, устройство продолжает работать,
  но пишет предупреждение в журнал. Для платы без расходомера
  отключите проверку: `flow_present=0`.

## Свернуть процесс и редактировать на ходу

Процесс продолжает работать, когда вы уходите с главного экрана в справку,
рецепты, журнал или настройки.

- На главном экране PWA и LCD есть кнопка **«Свернуть»**.
- На остальных экранах сверху появляется плашка **«Работа · этап ·
  температура»**; тап возвращает на главный экран.
- Остановка — только кнопкой «Стоп», E-STOP или по завершении программы.

Параметры можно менять тапом по строке в карточке «Отбор»:

- на ходу: T фиксации, время открыт/закрыт, гистерезис, декремент,
  минимальный open_time, таймер голов, конец хвостов, флегмовое число,
  мощность в ШИМ-режиме;
- только до старта: уставка PID и калибровка насоса; параметры
  безопасности не редактируются из интерфейса.

Заблокированная строка помечена замком и при тапе выдаёт сообщение.
На LCD те же параметры открываются в модальном окне (`−`/`+`/`OK`),
в Telegram — `/param <name> <value>`.

## Безопасность

- **E-STOP** (красная кнопка, нормально замкнутая): механически разрывает
  фазу 220 В и снимает нагрев; программно выключаются реле, нагрев
  блокируется до отпускания кнопки и сброса аварии. После — устраните
  причину и выполните сброс («Сброс аварии» в меню или
  `POST /api/safety`).
- **Датчик уровня** (поплавок): если жидкости нет, нагрев блокируется
  без аварийной остановки процесса — появится уведомление в Telegram
  и запись в журнале.
- **Telegram**: при E-STOP, аварии и низком уровне приходит сообщение.
  Настройка — раздел 6.5 `SETUP.md`. Бот также принимает команды
  `/status`, `/run`, `/stop`, `/power N`, `/log` и inline-кнопки — только
  из сохранённого chat_id; загрузка профиля из бота не поддерживается.
- **Не открывайте API в интернет.** Устройство предназначено для локальной
  сети (или VPN).

## Калибровка насоса

1. Меню → «Диагностика → Тест исполнителей» (нужен сервисный режим).
2. Нажмите «Насос → 10 мл».
3. Замерьте фактический объём мерным цилиндром.
4. Введите фактическое значение: коэффициент пересчитается как
   `steps_per_ml_new = steps_per_ml_old × 10 / факт_мл`.
5. Сохраните через `POST /api/config {"steps_per_ml": N}`.

## Выбор режима отбора

В «Настройках»:

- **Клапан** — быстрый отбор по времени/доле открытия; расход берётся из
  калибровки `flow_mlmin`;
- **Насос** — точное дозирование по объёму (мл).

## Обновление прошивки

1. Меню → «Прошивка (FOTA)» или `POST /api/ota/url` с HTTPS-ссылкой на `.bin`.
2. Устройство скачает и перезапишет резервный раздел, затем перезагрузится.
3. Первые 30 с — самопроверка (`OTA_CONFIRM_STABLE_MS`). Если всё в порядке,
   прошивка закрепляется; если что-то не так — **автоматический откат**
   на предыдущую версию. Ручное подтверждение — `POST /api/ota/confirm`.

Не отключайте питание во время обновления. При откате устройство вернётся
к прежней прошивке и запишет причину в журнал.

---

## Резервная копия настроек

- Сохранить: меню «Экспорт» или `POST /api/config/export` → `cfg.json` на SD.
- Восстановить: `POST /api/config/import` после замены платы.
- Ключи API в обычную копию **не входят** — для полного переноса добавьте
  `"secrets":true`.
- Отправить копию в Telegram: `POST /api/backup/telegram` — файл
  `automatika_backup.json` придёт в чат, указанный в настройках бота.

## Профили, автотюнинг и продолжение сессии

- **Профили** — сохранённые наборы уставок (например, «зерно», «фрукты»).
  Меню → «Профили» или `GET/POST/DELETE /api/profiles`. Файлы лежат во
  внутренней LittleFS и переживают перезагрузку.
- **Автотюнинг PID** — запускается из меню или
  `POST /api/autotune {"target":78.5}`. Занимает до часа; при аварии или
  E-STOP отменяется, найденные коэффициенты сохраняются только после
  успешного завершения.
- **Продолжение сессии** — если питание пропало во время работы,
  устройство предложит восстановить уставки и счётчики
  (`GET/POST /api/session`). Нагрев при восстановлении **не включается**:
  запуск выполняется обычной командой со всеми проверками.
- **Язык** — RU/EN, переключается в настройках или
  `POST /api/i18n {"lang":"en"}`.

## Ограничение частоты запросов

API принимает не более **10 запросов в секунду** (всплеск до 20). При
превышении возвращается `429 Too Many Requests` — это защита от
случайных циклов и внешних сканеров. Веб-интерфейс и WebSocket работают
штатно.

## Журнал событий и состояние устройства

- Журнал: `GET /api/events` (последние 200 событий) или меню «Диагностика».
- Состояние: `GET /api/health` (память, uptime, SD, датчики, аварии).

## Что делать при срабатывании E-STOP

1. Не паникуйте — нагрев уже отключён.
2. Проверьте: не перегрет ли куб, не забит ли клапан, не выкипела ли
   жидкость, не переполнена ли ёмкость.
3. Устраните причину.
4. Отпустите кнопку E-STOP и выполните сброс аварии.
5. Проверьте журнал: меню «Диагностика → Журнал» или `GET /api/events`.

Если откат произошёл после обновления — прошивка вернулась к предыдущей;
стоит повторить обновление и проверить версию по `GET /api/ota`.

## Датчики, алгоритмы и регуляторы (V0.6 beta)

- **Температура** проходит валидацию, медиану по 5, Калман и компенсацию
  давления. Выбросы 85/−127 °C отбрасываются; при невалидном датчике
  интерфейс показывает `--.-°`.
- **Алгоритм отбора** выбирается в «Подготовка → Вариант отбора»:
  классический, тренд или адаптивный. Тренд реагирует на скорость роста
  температуры, адаптивный сочетает его с классическим гистерезисом.
- **Внешний регулятор мощности**: KVIC, РМВ-К, SEM или SSR. UART — только
  через оптронную развязку, общая земля с силовой частью недопустима.
  При `-1` в пинах драйвер не активируется, нагрев идёт через DAC.
- **Проверка конфликтов**: повторный старт заблокирован, `open/close`
  пересчитываются согласованно, заблокированные параметры помечены замком.

## Частые вопросы

**Устройство не отвечает на API-запросы.** Проверьте заголовок `X-API-Key`;
если ключ не задан, API закрыт. Первый ключ создаётся кнопкой
«Сгенерировать на устройстве» в Настройках PWA (bootstrap разрешён только
пока ключ не создан).

**Приложение показывает «нет связи».** Проверьте Wi-Fi (`GET /api/health`,
поле `wifi_rssi`) и DNS; журнал событий покажет ошибки сети.

**Почему Telegram-сообщения приходят редко?** Уведомления обрабатываются
по очереди с интервалом не чаще одного в 2 с, чтобы не блокировать
управление нагревом.
